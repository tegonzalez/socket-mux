# socket-mux Design

## Purpose

Describe the intended architecture of socket-mux for authors who implement, extend or reconsider it: one program that, in TX or RX mode, carries one input stream, or a generated pattern, over N UDP lanes and reconstitutes it. The [specification](spec.md) owns consumer-visible behavior and terminology; this design owns mechanism, rationale and design decisions. Proposals awaiting a decision are in the [roadmap](roadmap.md).

## Architecture

- **Program.** One program has two modes, TX and RX, exposed as CLI subcommands: TX and RX subcommands and a `tx-pat` subcommand (SM-D1). Its options, defaults, precedence and exit statuses are open (OD-9, OD-14).
- **TX path.** TX reads one input and splinters its byte stream efficiently into N UDP lanes, each on a different port, selected from a base port incremented by one by default (SM-D4). Every datagram carries a header (SM-D2), whose layout is open (OD-12). The policy that assigns slices to lanes is open (OD-4).
- **TX input.** The `tx` subcommand reads one TCP connection on localhost, standard input (`-`) or a file, like netcat (SM-D1); how the operator selects among them is open (OD-17). The `tx-pat` subcommand instead generates a continuous pseudorandom "adler pattern" from a random seed, or from a fixed seed set by an option (SM-D1); the pattern format and the seed option are open (OD-18, OD-19).
- **RX path.** RX listens "on a particular port plus one with a default number of slices" (SM-D5), on base port to base port + N - 1 (SM-D11). It reads each datagram header, sequences slices on reconstitution, determines packet loss and the length of that loss, and reconstitutes the original stream. Where RX delivers that stream (OD-16) and what it emits where it detects loss (OD-15) are open.
- **Loss.** Neither mode retransmits, so the channel is lossy (SM-D3).
- **Seam.** The UDP datagram, a header followed by slice data and at most the [datagram size](spec.md#terminology), is the one seam between TX and RX; this project owns both sides. The header layout is open (OD-12), and no contract document exists.
- **Verification loop.** TX and RX can be placed back to back in a verification loop (SM-D6). With `tx-pat` as TX, RX's output is validated against the fixed-seed pattern, and validation recovers after any UDP loss; the resynchronization mechanism and the validator are open (OD-19, OD-20).
- **Delivery order and timeout.** RX delivers strictly in sequence order. It settles every gap and the end of the stream with one timeout T, under the rules the [specification](spec.md#semantics) states, and times them from arrival times (SM-D19).
- **RX ordering.** RX holds datagrams in a fixed arena and orders them in a wheel indexed by sequence number, then hands them to a FIFO that feeds the TCP output (SM-D24).
- **Allocation.** Neither mode allocates heap memory per datagram; both draw buffers from preallocated pools (SM-D25).
- **I/O model.** TX and RX are event-driven (SM-D20): each task waits on socket readiness, I/O completion, a channel or a timer deadline, and nothing spins or wakes on a fixed interval.
- **Platforms.** One code base targets Linux, macOS and Windows, and every dependency is cross-platform (SM-D7).

```text
TCP (localhost), stdin, file or pattern -> TX -> UDP lane 1 .. UDP lane N (N >= 1) -> RX -> original stream
```

## Design Decisions

Status `current` marks the intended design.

### SM-D1 One Program With TX And RX Subcommands

| Field             | Value                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The program has two modes, transmit (TX) and receive (RX), exposed as a CLI with TX and RX subcommands, handling both sides. TX also has a `tx-pat` subcommand whose input is a generated pseudorandom pattern instead of an input stream. The TX subcommand reads its stream from one TCP connection on localhost, from standard input (`-`) or from a file. |
| Rationale         | One program handles both sides of the link. Standard input and file input make TX act like a netcat that splinters its input and allows reassembly on the remote end; the pattern lets RX's output be validated against a known pattern.                                                                                                                      |
| Alternatives      | None recorded.                                                                                                                                                                                                                                                                                                                                                |
| Rejection reason  | None recorded.                                                                                                                                                                                                                                                                                                                                                |
| Affected surfaces | SM-P01, SM-P02, SM-P03, SM-P10, SM-P11                                                                                                                                                                                                                                                                                                                        |
| Status            | current                                                                                                                                                                                                                                                                                                                                                       |

### SM-D11 RX Listen Ports

| Field             | Value                                                                                                                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | Lanes are indexed 0 to N - 1, and lane k uses UDP port base port + k on both TX and RX. "A particular port plus one with a default number of slices" means RX listens on base port to base port + N - 1, the same ports TX sends to. |
| Rationale         | TX uses base port, base port + 1, ..., base port + N - 1 (SM-D4), so RX binding the same range needs only one shared base port and N.                                                                                                |
| Alternatives      | RX listens on one port, the base port plus one.                                                                                                                                                                                      |
| Rejection reason  | One port cannot receive N lanes that TX sends to N different ports.                                                                                                                                                                  |
| Affected surfaces | SM-P06; `--base-port`, `--streams`, `--bind`                                                                                                                                                                                         |
| Status            | current                                                                                                                                                                                                                              |

### SM-D19 Inter-Packet Delay Timeout

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX has one timeout T, set by a global command-line option, default 10 s. RX never delivers out of sequence, and it applies timeout rules A and B as the [specification](spec.md#semantics) states them. RX records each datagram's arrival time and checks the stored times against a monotonic clock. There is no timer per packet. The end-of-stream datagram goes through the same in-sequence path as every other datagram. RX waits on one deadline (SM-D24). The option's spelling is PROPOSAL (SM-D21). |
| Rationale         | Each run of missing datagrams gets the full timeout T from the datagram before it. A sender that stops, or a lost end-of-stream datagram, still ends the stream T after the last datagram. Nothing is delivered out of sequence. Timestamps checked against one clock need no timer per packet.                                                                                                                                                                                                                |
| Alternatives      | A timer per held datagram; a timer per lane; timing a gap from the first datagram held after it; separate timeouts for gap expiry and for end of stream; RX waits until it is stopped.                                                                                                                                                                                                                                                                                                                         |
| Rejection reason  | RX has one timeout T, a gap is timed from the datagram before it, and multiple timers are ruled out. A per-lane timer fires on a dead lane while the others carry data. Waiting until stopped leaves a lost end of stream open.                                                                                                                                                                                                                                                                                |
| Affected surfaces | Global options; RX reordering and loss declaration; RX output; SM-P06, SM-P09                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Status            | current                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

### SM-D20 Event-Driven I/O

| Field             | Value                                                                                                                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | socket-mux never busy-waits or polls, anywhere. TX and RX I/O is fully event-driven, with tokio or an equivalent. Each wait is on socket readiness or I/O completion, a channel, or a timer deadline, so RX keeps no CPU busy. |
| Rationale         | RX must keep no CPU busy, and the code must be professional. A busy-polling RX holds one CPU core at 100% while idle.                                                                                                          |
| Alternatives      | Busy-polling the sockets; sleeping and polling on an interval.                                                                                                                                                                 |
| Rejection reason  | Busy polling burns a core while idle; interval polling adds latency and still wakes the CPU. Both are disallowed.                                                                                                              |
| Affected surfaces | TX and RX I/O loops; RX's timeout and reorder waits                                                                                                                                                                            |
| Status            | current                                                                                                                                                                                                                        |

### SM-D24 RX Wheel, Arena And FIFO

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX holds datagrams in a preallocated arena of equal buffers, each one datagram of the datagram size; there are no variable-sized buffers. The buffer count W is the arena size ÷ datagram size. The wheel is a ring of W slots indexed by sequence number mod W; each slot is tagged with the exact sequence number it holds and records its arrival time, and an occupancy bitmap marks the full slots. The slot array and the bitmap are fixed overhead outside the arena. Per lane, RX takes a buffer from the arena, receives one datagram into it and places the buffer's reference in the wheel slot of its sequence number. RX serves the wheel in sequence order: each present slot at next moves, by reference, to an ordered, gap-free FIFO that feeds the TCP output, and its buffer returns to the arena when its TCP write completes. One task owns the arena, the wheel and the FIFO, so nothing is locked. RX waits on one deadline, the earlier of rule A's and rule B's expiry, in the same wait as socket readiness. The [specification](spec.md#semantics) owns the arena, drain, late and duplicate rules this structure applies. PROPOSAL: RX keeps one buffer back as its receive target, so it can read and drop the newest datagram under the drain limit; a drained sequence number's slot is marked lost, so its later expiry logs no second loss gap. |
| Rationale         | The wheel places and finds each datagram by its sequence number in O(1). Equal buffers from one arena fix RX's memory at the configured size. One owner needs no locks, and one deadline lets RX sleep without polling (SM-D20).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Alternatives      | A heap ordered by sequence number.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Rejection reason  | A heap takes every datagram after a second open gap and costs O(log H) per insert, where H is the number of datagrams held.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Affected surfaces | RX reordering and loss declaration; RX output; SM-P09, SM-P14, SM-P15                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Status            | current                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

### SM-D25 No Heap Allocation In The Critical Path

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | TX and RX allocate no heap memory in the critical path, the per-datagram work of reading or generating input, sending, receiving, ordering and writing output. Fixed, O(1) allocation from preallocated pools is permitted on both sides. TX takes each datagram's buffer from a fixed pool of datagram-size buffers, reads or generates the payload after the header room, writes the header, sends the datagram and returns the buffer. RX uses the arena (SM-D24). Zero copy here means no heap allocation and no extra user-space copy; the kernel copy between each socket and a pool buffer is unavoidable. |
| Rationale         | Heap allocation per datagram costs time and memory that grow with the rate; a fixed pool costs neither.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Alternatives      | None recorded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Rejection reason  | None recorded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Affected surfaces | TX path; RX path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Status            | current                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Failure Modes

- **Datagram loss.** RX determines packet loss and the length of that loss from the headers; nothing is retransmitted (SM-D3). What RX emits where it detects loss is open (OD-15). RX declares loss only under the [specification's](spec.md#semantics) timeout rules and loss limits (SM-D19, SM-D24).
- **Deep reorder or fast burst.** A datagram W or more ahead of next triggers the arena limit before T (SM-D24).
- **Stalled TCP output.** Buffers wait for their TCP writes until the arena is full, then the drain limit drops new datagrams (SM-D24).
- **Dead lane.** RX reports every gap a later datagram exposes. If the dead lane carried the end-of-stream datagram, timeout rule B ends the stream T after the last datagram (SM-D19).
