# socket-mux Design

## Purpose

Describe the intended architecture of socket-mux for authors who implement, extend or reconsider it: one program that, in TX or RX mode, carries one input stream, or a generated pattern, over N UDP lanes and reconstitutes it. The [specification](spec.md) owns consumer-visible behavior and terminology; this design owns mechanism, rationale and design decisions. Prospects are in the [roadmap](roadmap.md).

## Architecture

- **Program.** One program has two modes, TX and RX, exposed as CLI subcommands: TX and RX subcommands and a `tx-pat` subcommand ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)). The [specification](spec.md#command-line) owns its options, defaults, precedence and exit statuses.
- **TX path.** TX reads one input and splinters its byte stream efficiently into N UDP lanes, each on a different port, selected from a base port incremented by one by default ([TX Splinters Over N Ports](#tx-splinters-over-n-ports)). Every datagram carries a header ([Header Per UDP Datagram](#header-per-udp-datagram)), whose layout the [specification](spec.md#datagram-header) owns. This design does not fix the policy that assigns slices to lanes.
- **TX input.** The `tx` subcommand reads one TCP connection on localhost, standard input (`-`) or a file, like netcat ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)); the [specification](spec.md#command-line) owns how the operator selects among them. The `tx-pat` subcommand instead generates a continuous pseudorandom "adler pattern" from a random seed, or from a fixed seed set by an option ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)). The specification owns the seed option, and this design does not fix the pattern format.
- **RX path.** RX listens on base port to base port + N - 1 ([RX Listen Ports](#rx-listen-ports)). It reads each datagram header, sequences slices on reconstitution, determines packet loss and the length of that loss, and reconstitutes the original stream ([RX Reconstitutes The Stream](#rx-reconstitutes-the-stream)). The [specification](spec.md#public-surface) owns where RX delivers that stream and what it emits where it detects loss.
- **Loss.** Neither mode retransmits, so the channel is lossy ([No Retransmission](#no-retransmission)).
- **Seam.** The UDP datagram, a header followed by slice data and at most the [datagram size](spec.md#terminology), is the one seam between TX and RX; this project owns both sides. The [specification](spec.md#datagram-header) owns the header layout, and no contract document exists.
- **Verification loop.** TX and RX can be placed back to back in a verification loop ([Back-To-Back Verification Loop](#back-to-back-verification-loop)). With `tx-pat` as TX, RX's output is validated against the fixed-seed pattern, and validation recovers after any UDP loss. This design does not fix the resynchronization mechanism or the validator.
- **Delivery order and timeout.** RX delivers strictly in sequence order. It settles every gap and the end of the stream with one timeout T, under the rules the [specification](spec.md#semantics) states, and times them from arrival times ([Inter-Packet Delay Timeout](#inter-packet-delay-timeout)).
- **RX ordering.** RX holds datagrams in a fixed arena and orders them in a wheel indexed by sequence number, then hands them to a FIFO that feeds the TCP output ([RX Wheel, Arena And FIFO](#rx-wheel-arena-and-fifo)).
- **Allocation.** Neither mode allocates heap memory per datagram; both draw buffers from preallocated pools ([No Heap Allocation In The Critical Path](#no-heap-allocation-in-the-critical-path)).
- **I/O model.** TX and RX are event-driven ([Event-Driven I/O](#event-driven-io)): each task waits on socket readiness, I/O completion, a channel or a timer deadline, and nothing spins or wakes on a fixed interval.
- **Platforms.** One code base targets Linux, macOS and Windows, and every dependency is cross-platform ([Cross-Platform Dependencies](#cross-platform-dependencies)).

```text
TCP (localhost), stdin, file or pattern -> TX -> UDP lane 1 .. UDP lane N (N >= 1) -> RX -> original stream
```

### RX Listen Ports

| Field             | Value                                                                                                                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | Lanes are indexed 0 to N - 1, and lane k uses UDP port base port + k on both TX and RX. RX listens on base port to base port + N - 1, the same ports TX sends to.                                                                    |
| Rationale         | TX uses base port, base port + 1, ..., base port + N - 1 ([TX Splinters Over N Ports](#tx-splinters-over-n-ports)), so RX binding the same range needs only one shared base port and N.                                              |
| Alternatives      | RX listens on one port, the base port plus one.                                                                                                                                                                                      |
| Rejection reason  | One port cannot receive N lanes that TX sends to N different ports.                                                                                                                                                                  |
| Affected surfaces | SM-P06; `--base-port`, `--lanes`, `--bind`                                                                                                                                                                                           |

### Inter-Packet Delay Timeout

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX has one timeout T, set by a global command-line option, default 10 s. RX never delivers out of sequence, and it applies timeout rules A and B as the [specification](spec.md#semantics) states them. RX records each datagram's arrival time and checks the stored times against a monotonic clock. There is no timer per packet. The end-of-stream datagram goes through the same in-sequence path as every other datagram. RX waits on one deadline ([RX Wheel, Arena And FIFO](#rx-wheel-arena-and-fifo)). |
| Rationale         | Each run of missing datagrams gets the full timeout T from the datagram before it. A sender that stops, or a lost end-of-stream datagram, still ends the stream T after the last datagram. Nothing is delivered out of sequence. Timestamps checked against one clock need no timer per packet.                                                                                                                                                                                                                  |
| Alternatives      | A timer per held datagram; a timer per lane; timing a gap from the first datagram held after it; separate timeouts for gap expiry and for end of stream; RX waits until it is stopped.                                                                                                                                                                                                                                                                                                                           |
| Rejection reason  | RX has one timeout T, a gap is timed from the datagram before it, and multiple timers are ruled out. A per-lane timer fires on a dead lane while the others carry data. Waiting until stopped leaves a lost end of stream open.                                                                                                                                                                                                                                                                                  |
| Affected surfaces | Global options; RX reordering and loss declaration; RX output; SM-P06, SM-P09                                                                                                                                                                                                                                                                                                                                                                                                                                    |

### Event-Driven I/O

| Field             | Value                                                                                                                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | socket-mux never busy-waits or polls, anywhere. TX and RX I/O is fully event-driven, with tokio or an equivalent. Each wait is on socket readiness or I/O completion, a channel, or a timer deadline, so RX keeps no CPU busy. |
| Rationale         | RX must keep no CPU busy, and the code must be professional. A busy-polling RX holds one CPU core at 100% while idle.                                                                                                          |
| Alternatives      | Busy-polling the sockets; sleeping and polling on an interval.                                                                                                                                                                 |
| Rejection reason  | Busy polling burns a core while idle; interval polling adds latency and still wakes the CPU. Both are disallowed.                                                                                                              |
| Affected surfaces | TX and RX I/O loops; RX's timeout and reorder waits                                                                                                                                                                            |

### RX Wheel, Arena And FIFO

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX holds datagrams in a preallocated arena of equal buffers, each one datagram of the datagram size; there are no variable-sized buffers. The buffer count W is the arena size ÷ datagram size. The wheel is a ring of W slots indexed by sequence number mod W; each slot is tagged with the exact sequence number it holds and records its arrival time, and an occupancy bitmap marks the full slots. The slot array and the bitmap are fixed overhead outside the arena. Per lane, RX takes a buffer from the arena, receives one datagram into it and places the buffer's reference in the wheel slot of its sequence number. The wheel starts at the first datagram RX receives: older datagrams that arrive within T of it are placed normally, and once T has passed RX declares the older sequence numbers still missing lost ([specification](spec.md#semantics), start of stream). RX serves the wheel in sequence order: each present slot at next moves, by reference, to an ordered, gap-free FIFO that feeds the TCP output, and its buffer returns to the arena when its TCP write completes. One task owns the arena, the wheel and the FIFO, so nothing is locked. RX waits on one deadline, the earlier of rule A's and rule B's expiry, in the same wait as socket readiness. The [specification](spec.md#semantics) owns the arena, drain, late and duplicate rules this structure applies.                                                                                                                                                                                                                  |
| Rationale         | The wheel places and finds each datagram by its sequence number in O(1). Equal buffers from one arena fix RX's memory at the configured size. One owner needs no locks, and one deadline lets RX sleep without polling ([Event-Driven I/O](#event-driven-io)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Alternatives      | A heap ordered by sequence number.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Rejection reason  | A heap takes every datagram after a second open gap and costs O(log H) per insert, where H is the number of datagrams held.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Affected surfaces | RX reordering and loss declaration; RX output; SM-P09, SM-P14, SM-P15                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### No Heap Allocation In The Critical Path

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | TX and RX allocate no heap memory in the critical path, the per-datagram work of reading or generating input, sending, receiving, ordering and writing output. Fixed, O(1) allocation from preallocated pools is permitted on both sides. TX takes each datagram's buffer from a fixed pool of datagram-size buffers, reads or generates the payload after the header room, writes the header, sends the datagram and returns the buffer. RX uses the arena ([RX Wheel, Arena And FIFO](#rx-wheel-arena-and-fifo)). Zero copy here means no heap allocation and no extra user-space copy; the kernel copy between each socket and a pool buffer is unavoidable. |
| Rationale         | Heap allocation per datagram costs time and memory that grow with the rate; a fixed pool costs neither.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Alternatives      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Rejection reason  |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Affected surfaces | TX path; RX path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

### Sequence Width Is A Build Constant

| Field             | Value                                                                                                                                                                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The sequence width S is a compile-time constant, 32 bits in normal builds. Builds with 8 and 16 bits test rollover. Sequence numbers roll over at every width; the [specification](spec.md#semantics) owns the comparison and the fatal half-space gap. |
| Rationale         | A narrow build reaches rollover within a short run, so rollover is exercised in test instead of once every 2^32 datagrams.                                                                                                                              |
| Alternatives      |                                                                                                                                                                                                                                                         |
| Rejection reason  |                                                                                                                                                                                                                                                         |
| Affected surfaces | SM-P05; datagram header; TX path; RX path                                                                                                                                                                                                               |

### Datagram Header Layout

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The per-datagram header ([Header Per UDP Datagram](#header-per-udp-datagram)) is 14 + S/8 bytes in network byte order, 18 for the normal 32-bit sequence width of [Sequence Width Is A Build Constant](#sequence-width-is-a-build-constant): magic, version, flags, payload length, sequence and stream offset, as laid out in the [specification](spec.md#datagram-header).                                                                                                                                                                                                           |
| Rationale         | magic: RX discards stray datagrams that reach its ports. version: the layout can change without misreading old datagrams. flags: the end-of-stream bit tells RX that the TCP stream closed, so RX can close its output. payload length: RX knows how many slice bytes follow, independent of datagram padding. sequence: an S-bit global counter orders slices across all N lanes and counts lost slices; it rolls over ([Sequence Width Is A Build Constant](#sequence-width-is-a-build-constant)). stream offset: gives the exact byte length of a loss gap when payload sizes vary. |
| Alternatives      | A sequence number without a stream offset.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Rejection reason  | Without a stream offset the byte length of a loss is known only if every payload has the same size.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Affected surfaces | SM-P05; TX path; RX path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

### Default Ports

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | The default UDP base port is 31000, so the default single lane uses 31000. TX accepts TCP ingress on 127.0.0.1:31100 by default, and RX delivers to 127.0.0.1:31200 by default.                                                                                                                                                                                                                                          |
| Rationale         | The default port is meant to be straightforward and above the typical range. 31000 is round and memorable, lies above the well-known ports (0 to 1023) and below every ephemeral range (Linux 32768 to 60999; IANA, Windows and macOS 49152 to 65535), and IANA lists 31000 to 31015 as unassigned, so N up to 16 stays inside that block. 31100 and 31200 follow the same logic in the unassigned block 31030 to 31336. |
| Alternatives      | A base port in the IANA dynamic range (49152 to 65535).                                                                                                                                                                                                                                                                                                                                                                  |
| Rejection reason  | It collides with ephemeral ports the operating system assigns to outgoing connections.                                                                                                                                                                                                                                                                                                                                   |
| Affected surfaces | SM-P03, SM-P04, SM-P07; CLI defaults                                                                                                                                                                                                                                                                                                                                                                                     |

### Output Under Loss

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | Where RX detects loss, it skips the lost bytes, keeps the order of the bytes it delivers, and logs the gap with its lost slice count (from sequence) and byte length (from stream offset), plus running totals. RX keeps one buffer back as its receive target, so it can read and drop the newest datagram under the drain limit; a drained sequence number's slot is marked lost, so its later expiry logs no second loss gap. |
| Rationale         | The channel is lossy with no retransmission ([No Retransmission](#no-retransmission)), so RX keeps the stream flowing and makes every loss visible.                                                                                                                                                                                                                                                                              |
| Alternatives      | Fill the gap with zero bytes of the lost length; end the stream at the first loss.                                                                                                                                                                                                                                                                                                                                               |
| Rejection reason  | Zero fill injects bytes the sender never sent; ending the stream turns every loss into a failure on a channel that is lossy by design.                                                                                                                                                                                                                                                                                           |
| Affected surfaces | SM-P07, SM-P09; RX path                                                                                                                                                                                                                                                                                                                                                                                                          |

### RX Delivery Over TCP

| Field             | Value                                                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX connects out over TCP to a configurable peer, `--connect`, default 127.0.0.1:31200, and writes the reconstituted stream to it.             |
| Rationale         | It mirrors TX's TCP ingress, so the pair forms a TCP-to-TCP link and a back-to-back verification loop needs only a TCP client and a TCP sink. |
| Alternatives      | RX listens for a TCP client; RX writes to standard output.                                                                                    |
| Rejection reason  | Listening adds a second accept step before data can flow; standard output does not give a TCP stream on the far side.                         |
| Affected surfaces | SM-P07; `--connect`                                                                                                                           |

Command options stay after the subcommand, and early usage errors stop a misconfigured side before it opens a socket.                                                                             |
| Alternatives      | Global options only before the subcommand.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

### TX Input Operand

| Field             | Value                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | `tx` takes an optional `INPUT` operand after its options. Absent, `tx` accepts one TCP connection at `--listen`. `-` reads standard input. Any other value is a file path. `--listen` with an `INPUT` operand, or more than one `INPUT` operand, is a usage error. End of file on standard input or the file is end of stream, as a TCP close is. |
| Rationale         | A `-` or path operand is the netcat and Unix convention, and keeping TCP as the default keeps the current `tx` invocation unchanged.                                                                                                                                                                                                              |
| Alternatives      | An `--input <PATH or ->` option; standard input as the default when no option is given.                                                                                                                                                                                                                                                           |
| Rejection reason  | An option is longer to type for the common file case; a standard-input default makes a `tx` started from a terminal wait for typed input instead of a TCP client.                                                                                                                                                                                 |
| Affected surfaces | SM-P03, SM-P11; `--listen`; CLI                                                                                                                                                                                                                                                                                                                   |

### TX-PAT Seed Option

| Field             | Value                                                                                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | `tx-pat --seed <u64>` (short `-s`) sets a fixed seed. Without it, `tx-pat` draws a random 64-bit seed at start and logs it at `info`, so any run can be repeated. |
| Rationale         | A fixed seed makes the pattern reproducible for validation; logging the random seed lets a failing random run be replayed.                                        |
| Alternatives      | A seed given as a string and hashed; no logging of the random seed.                                                                                               |
| Rejection reason  | A hashed string adds a second seed form to agree on; an unlogged random seed makes a failing run impossible to replay.                                            |
| Affected surfaces | SM-P10, SM-P12; CLI                                                                                                                                               |

## Failure Modes

- **Datagram loss.** RX determines packet loss and the length of that loss from the headers; nothing is retransmitted ([No Retransmission](#no-retransmission)). The [specification](spec.md#semantics) owns what RX emits where it detects loss. RX declares loss only under the [specification's](spec.md#semantics) timeout rules and loss limits ([Inter-Packet Delay Timeout](#inter-packet-delay-timeout), [RX Wheel, Arena And FIFO](#rx-wheel-arena-and-fifo)).
- **Deep reorder or fast burst.** A datagram W or more ahead of next triggers the arena limit before T ([RX Wheel, Arena And FIFO](#rx-wheel-arena-and-fifo)).
- **Stalled TCP output.** Buffers wait for their TCP writes until the arena is full, then the drain limit drops new datagrams ([RX Wheel, Arena And FIFO](#rx-wheel-arena-and-fifo)).
- **Dead lane.** RX reports every gap a later datagram exposes. If the dead lane carried the end-of-stream datagram, timeout rule B ends the stream T after the last datagram ([Inter-Packet Delay Timeout](#inter-packet-delay-timeout)).
