# socket-mux Design

## Purpose

Describe the architecture and mechanisms of socket-mux for authors implementing, extending or reconsidering it. The design covers one Rust binary carrying one input stream or generated pattern over N UDP lanes and reconstituting it, plus an independent pattern-checking subcommand.

## Orientation

The intended baseline is the existing Rust 2021 binary. TX and RX socket I/O use Tokio's current-thread runtime; `check-pat` reads standard input without opening a socket or starting that runtime. The inventory distinguishes intended responsibility from realized modules, with source paths as implementation evidence.

## Terminology

| Term                                     | Design use                                                                                                               |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| TX, RX                                   | Transmit and receive roles; consumer-visible meanings are owned by the [specification](spec.md#terminology).             |
| Lane, slice, sequence, session           | Units used to split, address and order the stream; exact meanings are owned by the [specification](spec.md#terminology). |
| Datagram header                          | The TX-to-RX contract carried on every UDP datagram; the [specification](spec.md#datagram-header) owns its exact layout. |
| Timeout T, RX memory limit, output limit | Independent RX waiting and capacity bounds; exact behavior is owned by the [specification](spec.md#semantics).           |

## Design Goals

- Carry one input stream over configurable UDP lanes and reconstitute it at RX (G1); one program supports both sides (G2).
- Order received slices and determine loss and its byte length without retransmission (G3, G4).
- Support a back-to-back verification loop with a generated pattern that remains locatable after loss (G6).
- Preserve cross-platform operation (G7). Configurable lane-count behavior (G5) remains a consumer requirement owned by the [specification](spec.md#public-surface).

## Architecture

- **Program.** One program has TX and RX network modes and the `tx`, `tx-pat`, `rx` and `check-pat` subcommands ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)). `check-pat` reads standard input and opens no socket. The [specification](spec.md#command-line) owns options, defaults, precedence and exit statuses.
- **TX path.** TX reads one input and splinters its byte stream efficiently into N UDP lanes, each on a different port, selected from a base port incremented by one by default ([TX Splinters Over N Ports](#tx-splinters-over-n-ports)). Sequence s is assigned to lane s mod N ([Round-Robin Slice Assignment](#round-robin-slice-assignment)). Every datagram carries a header ([Header Per UDP Datagram](#header-per-udp-datagram)), whose layout the [specification](spec.md#datagram-header) owns. TX sends lane k to `--remote` at base port + k.
- **TX input.** The `tx` subcommand reads one TCP connection on localhost, standard input (`-`) or a file, like netcat ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)); the [specification](spec.md#command-line) owns how the operator selects among them. The `tx-pat` subcommand generates an unpaced, continuous pseudorandom pattern from a random seed or `--seed` ([Self-Locating Adler Pattern Blocks](#self-locating-adler-pattern-blocks)). It sends no end-of-stream datagram, installs no signal handler, and runs until a send error or external termination. SIGINT uses the operating-system default disposition and commonly appears to the shell as status 130.
- **RX path.** RX listens on base port to base port + N - 1, the same ports TX sends to ([RX Listen Ports](#rx-listen-ports)). The operator supplies both sides the same lane count, base port and datagram size; there is no negotiation. RX reads each datagram header, sequences slices on reconstitution, determines packet loss and its length, and reconstitutes the original stream ([RX Reconstitutes The Stream](#rx-reconstitutes-the-stream)). The [specification](spec.md#public-surface) owns where RX delivers that stream and what it emits where it detects loss.
- **Loss.** Neither mode retransmits, so the channel is lossy ([No Retransmission](#no-retransmission)).
- **Seam.** The UDP datagram, a header followed by slice data and at most the [datagram size](spec.md#terminology), is the one seam between TX and RX, seam `SM-01`. The [specification](spec.md#datagram-header) owns the header layout.
- **Verification loop.** TX and RX can be placed back to back in a verification loop ([Back-To-Back Verification Loop](#back-to-back-verification-loop)). With `tx-pat` as TX, `check-pat` validates RX output against the pattern, with byte-wise resynchronization after loss ([Self-Locating Adler Pattern Blocks](#self-locating-adler-pattern-blocks), [Check-Pat Checker Subcommand](#check-pat-checker-subcommand)).
- **Delivery order and timeout.** RX delivers strictly in sequence order. It settles every gap and the end of the stream with one timeout T, under the rules the [specification](spec.md#semantics) states, and times them from arrival times ([Inter-Packet Delay Timeout](#inter-packet-delay-timeout)).
- **RX ordering.** RX orders datagrams in a wheel indexed by sequence number within a fixed RX memory limit, then hands them to a FIFO that feeds the TCP output ([RX Memory Limit, Wheel And FIFO](#rx-memory-limit-wheel-and-fifo)).
- **Allocation.** Neither mode allocates heap memory per datagram; both draw buffers from preallocated pools ([No Heap Allocation In The Critical Path](#no-heap-allocation-in-the-critical-path)).
- **I/O model.** TX and RX use Tokio's current-thread runtime and event-driven I/O ([Rust Crate Set](#rust-crate-set), [Event-Driven I/O](#event-driven-io)): tasks wait on socket readiness, I/O completion, a channel or a timer deadline, and nothing spins or wakes on a fixed interval.
- **Session.** TX assigns a random run identity in its header path; RX checks it before sequence placement and uses its existing end-of-stream path when the identity changes ([Session Identity And Restart](#session-identity-and-restart)). This is intended architecture; it does not assert verified realization.
- **Security.** The lane path has no encryption or authentication layer; an external VPN protects an untrusted link ([Trusted-Link Security Boundary](#trusted-link-security-boundary)).
- **Platforms.** One code base targets Linux, macOS and Windows, and every dependency is cross-platform ([Cross-Platform Dependencies](#cross-platform-dependencies)); first-release qualification is [First-Release Platform Targets](#first-release-platform-targets).


## Design Decisions

### Rust Crate Set

| Field             | Value                                                                                                                                                                                                                                                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | socket-mux is implemented in Rust. TX and RX socket I/O use Tokio's current-thread runtime. The crate set is `tokio` (runtime, macros, networking, I/O, synchronization, filesystem and time features), `socket2`, `bytes`, `windows-sys` for Windows Winsock, `lexopt`, `anyhow`, `log` and `env_logger`. |
| Rationale         | One cross-platform event-driven runtime serves socket I/O and deadline waits; `lexopt` supplies the command-line parser, and the remaining crates provide the existing socket, buffer, error and logging surfaces.                                                                                         |
| Alternatives      | Per-lane operating-system threads for the data path; `pico-args` instead of `lexopt`.                                                                                                                                                                                                                      |
| Rejection reason  | The current design uses one Tokio runtime for socket and timer readiness, and selects `lexopt` as the parser.                                                                                                                                                                                              |
| Affected surfaces | TX and RX I/O; CLI; platform dependencies                                                                                                                                                                                                                                                                  |

### One Program With TX And RX Subcommands

| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

The TX subcommand reads its stream from one TCP connection on localhost, from standard input (`-`) or from a file. |
| Rationale         | One program handles both sides of the link. ### Trusted-Link Security Boundary

| Field             | Value                                                                                                                                                                                                                         |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | Keep the lane path free of encryption and authentication. Use an external VPN, for example WireGuard, across untrusted networks; the [specification](spec.md#boundaries) owns the trusted/private-link boundary and exposure. |
| Rationale         | The tool is scoped to trusted or private links; protection across an untrusted path is supplied outside socket-mux.                                                                                                           |
| Alternatives      | Built-in lane encryption and authentication.                                                                                                                                                                                  |

### Session Identity And Restart

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | Add a random 16-bit session ID per TX run to every datagram header. TX logs the ID at startup. RX locks onto the first valid datagram's session, checks session before sequence placement, and routes a different session to its existing end-of-stream finalization path with a warning. A new stream uses a fresh RX; the [specification](spec.md#semantics) owns observable termination and no-resume behavior. This is the intended baseline, not a claim of verified implementation. |
| Rationale         | An explicit run identity lets RX distinguish a restart from late slices of the current run without scanning payloads or adding an application checksum. Reusing the finalization path preserves ordering, loss handling and TCP closure instead of mixing streams. A 16-bit ID adds two header bytes; its collision and stale-first-datagram limits are admitted in [known issues](known-issues.md#register).                                                                             |
| Alternatives      | No stream identity; seed a per-datagram application checksum.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Rejection reason  | Without identity, a new run's low sequence numbers look late until T ends the old stream. No per-datagram application checksum exists to seed; introducing one costs a full pass over every payload plus the header bytes. The pattern's per-block Adler-32 is separate from the datagram header.                                                                                                                                                                                         |
| Affected surfaces | SM-P05; TX header/startup logging; RX session gate and finalization; specification diagnostics S-17 and S-18; 24-byte header and 1428-byte default payload                                                                                                                                                                                                                                                                                                                                |

### RX Listen Ports

| Field             | Value                                                                                                                                                                                   |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | Lanes are indexed 0 to N - 1, and lane k uses UDP port base port + k on both TX and RX. RX listens on base port to base port + N - 1, the same ports TX sends to.                       |
| Rationale         | TX uses base port, base port + 1, ..., base port + N - 1 ([TX Splinters Over N Ports](#tx-splinters-over-n-ports)), so RX binding the same range needs only one shared base port and N. |
| Alternatives      | RX listens on one port, the base port plus one.                                                                                                                                         |
| Rejection reason  | One port cannot receive N lanes that TX sends to N different ports.                                                                                                                     |
| Affected surfaces | SM-P06; `--base-port`, `--lanes`, `--bind`                                                                                                                                              |

### Inter-Packet Delay Timeout

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX has one timeout T, set by a global command-line option, default 10 s. RX never delivers out of sequence, and it applies timeout rules A and B as the [specification](spec.md#semantics) states them. RX records each datagram's arrival time and checks the stored times against a monotonic clock. There is no timer per packet or separate TCP-output-stall timeout. The end-of-stream datagram goes through the same in-sequence path as every other datagram. RX waits on one deadline ([RX Memory Limit, Wheel And FIFO](#rx-memory-limit-wheel-and-fifo)). |
| Rationale         | Each run of missing datagrams gets the full timeout T from the datagram before it. A sender that stops, or a lost end-of-stream datagram, still ends the stream T after the last datagram. Nothing is delivered out of sequence. Timestamps checked against one clock need no timer per packet.                                                                                                                                                                                                                                                                     |
| Alternatives      | A timer per held datagram; a timer per lane; timing a gap from the first datagram held after it; separate timeouts for gap expiry and for end of stream; RX waits until it is stopped.                                                                                                                                                                                                                                                                                                                                                                              |
| Rejection reason  | RX has one timeout T, a gap is timed from the datagram before it, and multiple timers are ruled out. A per-lane timer fires on a dead lane while the others carry data. Waiting until stopped leaves a lost end of stream open.                                                                                                                                                                                                                                                                                                                                     |
| Affected surfaces | Global options; RX reordering and loss declaration; RX output; SM-P06, SM-P09                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

### Event-Driven I/O

| Field             | Value                                                                                                                                                                                                                         |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | socket-mux never busy-waits or polls, anywhere. TX and RX I/O is event-driven on Tokio's current-thread runtime. Each wait is on socket readiness or I/O completion, a channel, or a timer deadline, so RX keeps no CPU busy. |
| Rationale         | RX must keep no CPU busy, and the code must be professional. A busy-polling RX holds one CPU core at 100% while idle.                                                                                                         |
| Alternatives      | Busy-polling the sockets; sleeping and polling on an interval.                                                                                                                                                                |
| Rejection reason  | Busy polling burns a core while idle; interval polling adds latency and still wakes the CPU. Both are disallowed.                                                                                                             |
| Affected surfaces | TX and RX I/O loops; RX's timeout and reorder waits                                                                                                                                                                           |

### RX Memory Limit, Wheel And FIFO

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX holds datagrams in a preallocated pool of equal buffers whose total size is the RX memory limit (`--rx-memory`), each buffer one datagram of the datagram size; there are no variable-sized buffers. The [Hold capacity W](spec.md#terminology) is the RX memory limit ÷ datagram size, rounded down. The wheel is a ring of W slots indexed by sequence number mod W; each slot is tagged with the exact sequence number it holds and records its arrival time, and an occupancy bitmap marks the full slots. All W buffers can hold datagrams. The slot array, the bitmap and one extra datagram-size receive buffer are fixed overhead outside the RX memory limit. Per lane, RX takes a buffer from the pool, receives one datagram into it and places the buffer's reference in the wheel slot of its sequence number. The wheel starts at the first datagram RX receives: older datagrams that arrive within T of it are placed normally, and once T has passed RX declares the older sequence numbers still missing lost ([specification](spec.md#semantics), start of stream). RX serves the wheel in sequence order: each present slot at next moves, by reference, to an ordered, gap-free FIFO that feeds the TCP output, and its buffer returns to the pool when its TCP write completes. One task owns the pool, the wheel and the FIFO, so nothing is locked. RX waits on one deadline, the earlier of rule A's and rule B's expiry, in the same wait as socket readiness. The [specification](spec.md#semantics) owns the RX memory limit, output, late and duplicate rules this structure applies. |
| Rationale         | The wheel places and finds each datagram by its sequence number in O(1). Equal buffers from one pool keep RX's receive memory bounded by the configured limit. One owner needs no locks, and one deadline lets RX sleep without polling ([Event-Driven I/O](#event-driven-io)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Alternatives      | A heap ordered by sequence number.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Rejection reason  | A heap takes every datagram after a second open gap and costs O(log H) per insert, where H is the number of datagrams held.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Affected surfaces | RX reordering and loss declaration; RX output; SM-P09, SM-P14, SM-P15                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### No Heap Allocation In The Critical Path

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | TX and RX allocate no heap memory in the critical path, the per-datagram work of reading or generating input, sending, receiving, ordering and writing output. Fixed, O(1) allocation from preallocated pools is permitted on both sides. TX takes each datagram's buffer from a fixed pool of datagram-size buffers, reads or generates the payload after the header room, writes the header, sends the datagram and returns the buffer. RX uses the RX memory pool ([RX Memory Limit, Wheel And FIFO](#rx-memory-limit-wheel-and-fifo)). Zero copy here means no heap allocation and no extra user-space copy; the kernel copy between each socket and a pool buffer is unavoidable. |
| Rationale         | Heap allocation per datagram costs time and memory that grow with the rate; a fixed pool costs neither.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Alternatives      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Rejection reason  |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Affected surfaces | TX path; RX path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

### Sequence Width Is A Build Constant

| Field             | Value                                                                                                                                                                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The sequence width S is a compile-time constant, 64 bits in normal builds. Builds with 8 and 16 bits test rollover of the effective counter while retaining the fixed u64 wire field. Sequence numbers roll over at every width; the [specification](spec.md#semantics) owns the comparison and the fatal half-space gap. |
| Rationale         | A narrow build reaches rollover within a short run, so rollover is exercised in test instead of once every 2^64 datagrams.                                                                                                                                                                                                |
| Alternatives      |                                                                                                                                                                                                                                                                                                                           |
| Rejection reason  |                                                                                                                                                                                                                                                                                                                           |
| Affected surfaces | SM-P05; datagram header; TX path; RX path                                                                                                                                                                                                                                                                                 |

### Datagram Header Layout

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The per-datagram header ([Header Per UDP Datagram](#header-per-udp-datagram)) occupies 24 bytes, with a session ID and fixed u64 sequence field, as laid out in the [specification](spec.md#datagram-header). Reduced-width builds exercise counter rollover without changing the layout. Header version stays 1 during pre-alpha; version bumps begin with formal releases.                                                                                                                                                                                                                                                                                                                                                                                               |
| Rationale         | magic: RX discards stray datagrams that reach its ports. version: identifies the format family; pre-alpha wire changes retain version 1 rather than promising compatibility between pre-alpha builds. flags: the end-of-stream bit tells RX that the TCP stream closed, so RX can close its output. payload length: RX knows how many slice bytes follow, independent of datagram padding. session: identifies a TX run ([Session Identity And Restart](#session-identity-and-restart)). sequence: an S-bit effective global counter orders slices across all N lanes and counts lost slices; it rolls over ([Sequence Width Is A Build Constant](#sequence-width-is-a-build-constant)). stream offset: gives the exact byte length of a loss gap when payload sizes vary. |
| Alternatives      | A sequence number without a stream offset.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Rejection reason  | Without a stream offset the byte length of a loss is known only if every payload has the same size.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Affected surfaces | SM-P05; TX path; RX path                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

### Default Ports

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | The default UDP base port is 31000, so the default single lane uses 31000. TX accepts TCP ingress on 127.0.0.1:31100 by default, and RX delivers to 127.0.0.1:31200 by default.                                                                                                                                                                                                                                          |
| Rationale         | The default port is meant to be straightforward and above the typical range. 31000 is round and memorable, lies above the well-known ports (0 to 1023) and below every ephemeral range (Linux 32768 to 60999; IANA, Windows and macOS 49152 to 65535), and IANA lists 31000 to 31015 as unassigned, so N up to 16 stays inside that block. 31100 and 31200 follow the same logic in the unassigned block 31030 to 31336. |
| Alternatives      | A base port in the IANA dynamic range (49152 to 65535).                                                                                                                                                                                                                                                                                                                                                                  |
| Rejection reason  | It collides with ephemeral ports the operating system assigns to outgoing connections.                                                                                                                                                                                                                                                                                                                                   |
| Affected surfaces | SM-P03, SM-P04, SM-P07; CLI defaults                                                                                                                                                                                                                                                                                                                                                                                     |

### Output Under Loss

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | Where RX detects loss, it skips the lost bytes, keeps the order of the bytes it delivers, and logs the gap with its lost slice count (from sequence) and byte length (from stream offset), plus running totals. RX receives into its extra receive buffer when all W buffers are occupied, so it can read and drop the newest datagram under the output limit without overwriting a held datagram; a dropped sequence number's slot is marked lost, so its later expiry logs no second loss gap. |
| Rationale         | The channel is lossy with no retransmission ([No Retransmission](#no-retransmission)), so RX keeps the stream flowing and makes every loss visible.                                                                                                                                                                                                                                                                                                                                              |
| Alternatives      | Fill the gap with zero bytes of the lost length; end the stream at the first loss.                                                                                                                                                                                                                                                                                                                                                                                                               |
| Rejection reason  | Zero fill injects bytes the sender never sent; ending the stream turns every loss into a failure on a channel that is lossy by design.                                                                                                                                                                                                                                                                                                                                                           |
| Affected surfaces | SM-P07, SM-P09; RX path                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

### RX Delivery Over TCP

| Field             | Value                                                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX connects out over TCP to a configurable peer, `--connect`, default 127.0.0.1:31200, and writes the reconstituted stream to it.             |
| Rationale         | It mirrors TX's TCP ingress, so the pair forms a TCP-to-TCP link and a back-to-back verification loop needs only a TCP client and a TCP sink. |
| Alternatives      | RX listens for a TCP client; RX writes to standard output.                                                                                    |
| Rejection reason  | Listening adds a second accept step before data can flow; standard output does not give a TCP stream on the far side.                         |
| Affected surfaces | SM-P07; `--connect`                                                                                                                           |

### Command-Line Options

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The binary is named `socket-mux` and takes the `tx`, `tx-pat`, `rx` and `check-pat` subcommands, with command options after the subcommand and global options before or after it. All settings come from command-line options; there is no configuration file or environment-variable configuration. The option set, short forms, defaults, constraints, precedence, invalid combinations and exit statuses are those in the [specification](spec.md#command-line), independent of any argument-parsing library. The `tx` `INPUT` operand is [TX Input Operand](#tx-input-operand), the `tx-pat` seed is [TX-PAT Seed Option](#tx-pat-seed-option), and `check-pat` is [Check-Pat Checker Subcommand](#check-pat-checker-subcommand). |

Command options stay after the subcommand, and early usage errors stop a misconfigured side before it opens a socket.   |

### TX Input Operand

| Field             | Value                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | `tx` takes an optional `INPUT` operand after its options. Absent, `tx` accepts one TCP connection at `--listen`. `-` reads standard input. End of file on standard input or the file is end of stream, as a TCP close is. |
| Rationale         | A `-` or path operand is the netcat and Unix convention, and keeping TCP as the default keeps the current `tx` invocation unchanged.                                                                                                                                                                                                              |
| Alternatives      | An `--input <PATH or ->` option; standard input as the default when no option is given.                                                                                                                                                                                                                                                           |

### TX-PAT Seed Option

| Field             | Value                                                                                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | `tx-pat --seed <u64>` (short `-s`) sets a fixed seed. Without it, `tx-pat` draws a random 64-bit seed at start and logs it at `info`, so any run can be repeated. |
| Rationale         | A fixed seed makes the pattern reproducible for validation; logging the random seed lets a failing random run be replayed.                                        |

### Self-Locating Adler Pattern Blocks

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The `tx-pat` stream is unpaced and continuous, with no end-of-stream datagram; it installs no signal handler and runs until a send error or external termination. SIGINT uses the operating-system default disposition and commonly appears to the shell as status 130. Each 4096-byte block contains an 8-byte big-endian index, 4084 bytes of SplitMix64 output keyed by seed and index, and a 4-byte big-endian Adler-32 checksum of the preceding 4092 bytes. The generator initializes state with `seed XOR (index × 0x9E3779B97F4A7C15)` using wrapping 64-bit multiplication, advances standard SplitMix64 for each output word, emits words big-endian and truncates the final word to four bytes. |
| Rationale         | Per-block indices and checksums let an independent checker find a valid block after RX has removed any loss gap; the seed additionally lets it verify the generated body.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Alternatives      | Locate an unframed generator stream from the datagram stream offset; validate inside RX.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Rejection reason  | RX skips loss gaps and therefore does not preserve the source stream offsets; validation inside RX would not independently check RX output.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Affected surfaces | SM-P13; `tx-pat`; `check-pat`; verification loop                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

### Check-Pat Checker Subcommand

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | `socket-mux check-pat [--seed U64]` reads RX output from standard input, takes no operand and opens no socket. It scans for checksum-valid 4096-byte windows, also regenerating the payload when a seed is supplied, checks block-index order and resumes scanning one byte at a time after a gap. It prints one line with `blocks_ok`, `blocks_bad`, `resyncs`, `lost_bytes`, `skipped_bytes`, `trailing_bytes`, `first_index` and `last_index`; a missing index is `none`. It exits 0 for empty input or input with at least one valid block and no bad block, and 1 for bad blocks, nonempty input with no valid block, or read failure. |
| Rationale         | A checker in the same binary validates the receiver output without coupling validation to RX or requiring an extra program.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Alternatives      | A separate checker executable; validation only in the verification loop.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Rejection reason  | A separate executable adds another platform artifact, and RX-side validation would not be independent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Affected surfaces | SM-P16; CLI; pattern verification                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Component Responsibilities

| Role                  | Responsibility                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------ |
| TX (`tx`, `tx-pat`)   | Read or generate one stream, sequence slices, and send each datagram on its assigned lane. |
| RX (`rx`)             | Receive the lanes, order slices, account for loss, and deliver the remaining stream.       |
| Checker (`check-pat`) | Independently scan RX output and report pattern validity and resynchronization.            |

## API Shape

The package exposes a command-line binary, not a Rust library API ([`Cargo.toml`](../Cargo.toml), [`src/main.rs`](../src/main.rs)). The [specification](spec.md#public-surface) owns the CLI and the UDP datagram shape. `SM-01` is the only cross-role data seam; this design describes its architectural use and does not duplicate its field schema.

## Workflow And Data Flow

The operator configures both endpoints with the same lane count, base port and datagram size by hand; there is no negotiation. TX sends lane k to `--remote` at base port + k, while RX listens on those same ports. Sequence s is assigned to lane s mod N. TX awaits completion of each of its own UDP sends; RX sends no backpressure to TX. RX orders received data and applies the single timeout T and RX memory limit. A slow TCP consumer retains buffers until the memory limit is reached, after which the output limit drops new datagrams as loss. `tx-pat` supplies continuous blocks without an end marker; the independent checker reads the resulting RX output from standard input.

```text
TCP (localhost), stdin, file or pattern -> TX -> UDP lane 1 .. UDP lane N -> RX -> original stream
                                                               RX output -> check-pat
```

## Preservation Requirements

- Preserve the one-program TX/RX shape and separately callable checker ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)).
- Preserve round-robin lane assignment, the matching TX/RX port range, and manual far-end configuration ([Round-Robin Slice Assignment](#round-robin-slice-assignment), [RX Listen Ports](#rx-listen-ports)).
- Preserve lossy delivery without retransmission, and no RX-to-TX backpressure ([No Retransmission](#no-retransmission), [specification backpressure semantics](spec.md#semantics)).
- Preserve one timeout T, with no separate TCP-output-stall timeout ([Inter-Packet Delay Timeout](#inter-packet-delay-timeout)).
- Preserve the self-locating pattern and independent `check-pat` validation ([Self-Locating Adler Pattern Blocks](#self-locating-adler-pattern-blocks), [Check-Pat Checker Subcommand](#check-pat-checker-subcommand)).
- Preserve CLI-only settings, with no configuration file or environment-variable configuration ([Command-Line Options](#command-line-options)).

## Failure Modes

- **Datagram loss.** RX determines packet loss and the length of that loss from the headers; nothing is retransmitted ([No Retransmission](#no-retransmission)). The [specification](spec.md#semantics) owns what RX emits where it detects loss. RX declares loss only under the [specification's](spec.md#semantics) timeout rules and loss limits ([Inter-Packet Delay Timeout](#inter-packet-delay-timeout), [RX Memory Limit, Wheel And FIFO](#rx-memory-limit-wheel-and-fifo)).
- **Deep reorder or fast burst.** A datagram W or more ahead of next triggers the memory limit before T ([RX Memory Limit, Wheel And FIFO](#rx-memory-limit-wheel-and-fifo)).
- **Stalled TCP output.** TX waits only for completion of its own UDP sends; RX applies no backpressure to TX. Buffers wait for their TCP writes until RX memory is full, then the output limit drops new datagrams ([RX Memory Limit, Wheel And FIFO](#rx-memory-limit-wheel-and-fifo)).
- **TX restart or stale session.** A different session invokes stream finalization, not a sequence reset or resume ([Session Identity And Restart](#session-identity-and-restart)); same-ID collisions and stale-first arrivals remain [accepted limits](known-issues.md#register).
- **Dead lane.** RX reports every gap a later datagram exposes. If the dead lane carried the end-of-stream datagram, timeout rule B ends the stream T after the last datagram ([Inter-Packet Delay Timeout](#inter-packet-delay-timeout)).

## Acceptance Criteria

- **AC-01:** TX assigns sequence s to lane s mod N and sends lane k to the same base-port-plus-k endpoint on which RX listens, as required by the [specification](spec.md#semantics).
- **AC-02:** RX delivers in order and applies the specified timeout, RX memory limit and output limit without retransmission or feedback to TX ([specification](spec.md#semantics)).
- **AC-03:** `tx-pat` output can be sent through RX and independently checked by `check-pat`, including recovery after loss ([Back-To-Back Verification Loop](#back-to-back-verification-loop), [specification validation](spec.md#validation)).
- **AC-04:** Settings remain command-line-only and both endpoints rely on operator agreement rather than negotiation ([Command-Line Options](#command-line-options), [specification](spec.md#semantics)).
