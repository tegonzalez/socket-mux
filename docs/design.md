# socket-mux Design

## Purpose

Describe the architecture and mechanisms of socket-mux for authors implementing, extending or reconsidering it. The design covers one Rust binary carrying one input stream or generated pattern over N UDP lanes and reconstituting it, plus an independent pattern-checking subcommand.

## Orientation

The intended baseline is a Rust 2021 binary whose TX and RX run on blocking operating-system threads without an async runtime ([Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io)); `check-pat` reads standard input and opens no socket. The TX producer and lane send threads, the RX lane, reorder and writer threads, the wait policy, the loss and summary reporter and signal handling are realized in the source tree. The datagram-size default derived from the adapter MTU and its over-MTU warning ([Datagram Size From Adapter MTU](#datagram-size-from-adapter-mtu)) are realized in `src/mtu.rs`. Not realized: the [ipd](#inter-packet-delay) loss rules and `rx --ipd`, the [RX arena](#rx-ring-of-rings-and-writer-staging), the [session abort](#session-identity-and-restart), [byte-count suffixes](#command-line-options), the [reporter's](#loss-and-summary-reporter) wait-free ring, loss warnings, delay and end reason, and [no pacing](#no-tx-pacing); the source tree applies a global `--timeout`, a shared wheel and a memory reserve, ends the stream with status 0 on a different session, takes plain integer byte counts, prints interval reports and start-up lines at `info` and paces `tx-pat` with `--ipd-ns`. Forbidden implementation patterns are in the [constraints](constraints.md).

## Terminology

| Term                                 | Design use                                                                                                                                                          |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TX, RX                               | Transmit and receive roles; consumer-visible meanings are owned by the [specification](spec.md#terminology).                                                        |
| Lane, slice, sequence, session       | Units used to split, address and order the stream; exact meanings are owned by the [specification](spec.md#terminology).                                            |
| Datagram header                      | The TX-to-RX contract carried on every UDP datagram; the [specification](spec.md#datagram-header) owns its exact layout.                                            |
| Ipd, hold capacity W, writer staging | RX's one waiting limit, its window, and its delivered datagrams awaiting their TCP write; exact behavior is owned by the [specification](spec.md#semantics).        |
| Ring of rings                        | The reorder thread's outer ring of W slots indexed by sequence number mod W, holding buffer pointers, with each contiguous held run recorded at its boundary slots. |
| Loss stretch, loss cause             | A run of slices RX declares lost together, and why; exact meanings are owned by the [specification](spec.md#terminology).                                           |
| Producer                             | The TX thread that reads or generates the input and frames datagrams for the lane send threads.                                                                     |
| Reorder thread                       | The one RX thread, the process's main thread, that owns the ring of rings and every ordering, loss-rule, loss-cause and session decision.                           |
| RX arena                             | The one preallocated region of the RX memory limit: W datagram-size buffers holding every RX datagram.                                                              |
| Free list                            | The lock-free list of unused pool or arena buffers that threads take from and return to, each in O(1).                                                              |
| Pressure flag                        | One atomic word that an RX lane receive thread raises when it finds the arena's free list empty and the TCP writer lowers when it returns a buffer.                 |
| Loss ring                            | The bounded lock-free queue of compact loss-stretch and out-of-sequence-delay entries from the reorder thread to the reporter; a push never waits.                  |
| Reporter                             | The low-priority thread that drains the loss ring and prints loss warnings and final summaries.                                                                     |

## Design Goals

- Carry one input stream over configurable UDP lanes and reconstitute it at RX (G1); one program supports both sides (G2).
- Order received slices and determine loss and its byte length without retransmission (G3, G4).
- Support a back-to-back verification loop with a generated pattern that remains locatable after loss (G6).
- Preserve cross-platform operation (G7). Configurable lane-count behavior (G5) remains a consumer requirement owned by the [specification](spec.md#public-surface).
- Let throughput scale with lanes toward line rate, keeping per-datagram work constant and off shared locks (G1).
- Use approximately no CPU while idle, and keep loss reporting from ever slowing the data path (G1, G3).

## Architecture

- **Program.** One program has TX and RX network modes and the `tx`, `tx-pat`, `rx` and `check-pat` subcommands ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)). `check-pat` reads standard input and opens no socket. The [specification](spec.md#command-line) owns options, defaults, precedence and exit statuses.
- **TX path.** TX reads one input and splinters its byte stream efficiently into N UDP lanes, each on a different port, selected from a base port incremented by one by default ([TX Splinters Over N Ports](#tx-splinters-over-n-ports)). Sequence s is assigned to lane s mod N ([Round-Robin Slice Assignment](#round-robin-slice-assignment)). Every datagram carries a header ([Header Per UDP Datagram](#header-per-udp-datagram)), whose layout the [specification](spec.md#datagram-header) owns. A producer thread frames datagrams and hands each lane's datagrams to that lane's send thread ([Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io)).
- **TX input.** The `tx` subcommand reads one TCP connection on localhost, standard input (`-`) or a file, like netcat ([One Program With TX And RX Subcommands](#one-program-with-tx-and-rx-subcommands)); the [specification](spec.md#command-line) owns how the operator selects among them. The `tx-pat` subcommand generates a pseudorandom pattern from a random seed or `--seed` ([Self-Locating Adler Pattern Blocks](#self-locating-adler-pattern-blocks)); it sends without pacing ([No TX Pacing](#no-tx-pacing)) and is endless unless `--bytes` ends it with an end-of-stream datagram ([TX-PAT Byte Count](#tx-pat-byte-count)).
- **RX path.** RX listens on base port to base port + N - 1, the same ports TX sends to ([RX Listen Ports](#rx-listen-ports)). The operator supplies both sides the same lane count, base port and datagram size; there is no negotiation. One receive thread per lane receives each datagram into an RX arena buffer and passes it to the one reorder thread, which applies the session and loss rules and hands ordered runs to the TCP writer thread ([RX Reconstitutes The Stream](#rx-reconstitutes-the-stream), [Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io)). The [specification](spec.md#public-surface) owns where RX delivers that stream and what it reports where it detects loss.
- **Loss.** Neither mode retransmits, so the channel is lossy ([No Retransmission](#no-retransmission)).
- **Seam.** The UDP datagram, a header followed by slice data and at most the [datagram size](spec.md#terminology), is the one seam between TX and RX, seam `SM-01`. The [specification](spec.md#datagram-header) owns the header layout.
- **Verification loop.** TX and RX can be placed back to back in a verification loop ([Back-To-Back Verification Loop](#back-to-back-verification-loop)). With `tx-pat` as TX, `check-pat` validates RX output against the pattern, with byte-wise resynchronization after loss ([Self-Locating Adler Pattern Blocks](#self-locating-adler-pattern-blocks), [Check-Pat Checker Subcommand](#check-pat-checker-subcommand)).
- **Delivery order and ipd.** RX delivers strictly in sequence order. It settles every gap and the end of the stream with one ipd, under the loss rules the [specification](spec.md#semantics) states, and times them from arrival times ([Inter-Packet Delay](#inter-packet-delay)).
- **RX ordering.** The reorder thread orders datagrams in a ring of rings indexed by sequence number and hands each in-order run by pointer to the TCP writer's staging; received, held and staged datagrams share the one arena of the RX memory limit ([RX Ring Of Rings And Writer Staging](#rx-ring-of-rings-and-writer-staging)). It alone makes ordering, loss-rule, loss-cause and session decisions.
- **Allocation.** Neither mode allocates heap memory per datagram; both draw buffers from preallocated pools through lock-free free lists ([No Heap Allocation In The Critical Path](#no-heap-allocation-in-the-critical-path)).
- **I/O and waiting.** TX and RX use blocking operating-system threads and no async runtime ([Rust Crate Set](#rust-crate-set), [Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io)). Socket waits are blocking calls; a thread waiting on a queue spins briefly, then backs off to a blocking park ([Wait Policy](#wait-policy)).
- **Reporting.** The reorder thread keeps exact loss counters and pushes compact loss-stretch and out-of-sequence-delay entries into a bounded lock-free ring that never blocks; a low-priority reporter thread drains it as fast as it can, prints grouped loss warnings, keeps the largest out-of-sequence delay and prints the TX and RX final summaries ([Loss And Summary Reporter](#loss-and-summary-reporter)).
- **Signals.** SIGINT and SIGTERM, and the Windows Ctrl-C and console-close events, stop the run; the reporter drains and prints the final summary before the process exits with 130 or 143 ([Signal Handling And Final Summary](#signal-handling-and-final-summary)).
- **Session.** TX assigns a random run identity in its header path; RX checks it before sequence placement and aborts when the identity changes ([Session Identity And Restart](#session-identity-and-restart)).
- **Security.** The lane path has no encryption or authentication layer; an external VPN protects an untrusted link ([Trusted-Link Security Boundary](#trusted-link-security-boundary)).
- **Platforms.** One code base targets Linux, macOS and Windows, and every dependency is cross-platform ([Cross-Platform Dependencies](#cross-platform-dependencies)); first-release qualification is [First-Release Platform Targets](#first-release-platform-targets).

### Deployment And Test Topology

The available test topology is two identical Linux x86_64 hosts, each with an AMD Ryzen AI Max+ PRO 495 and 32 threads, connected over 10GbE at a 1500-byte MTU and addressed over IPv4. The receiving host's 10GbE adapter runs one receive queue with a 256-entry receive ring. An administrator raised `net.core.rmem_max` and `net.core.wmem_max` to 67108864 bytes (64 MiB) on the Linux hosts with `sysctl -w`, which lasts until reboot; the Linux default for each is 4194304 bytes. Socket-buffer capacity is separate from the RX memory limit that bounds application-held datagrams. The repository's `scripts/link-sweep` harness drives two-host runs over lanes, RX `--udp-buffer`, TX pacing and `--datagram-size`, and records UDP, adapter and softnet counters on each host's local disk.

The intended deployment adds a headless Windows x86_64 peer as TX, receiving the cross-compiled `win64-x86_64` binary without a build environment on the peer. The performance goal is maximum throughput from Windows TX to Linux RX. The [roadmap](roadmap.md#r-39-per-layer-measurement-plan) owns measurement readiness and sequencing, including jumbo-MTU work, which waits for the Windows peer.

A pattern run sent 2 GB with `tx-pat --bytes` and checked RX output with `check-pat`; a file run sent a 2 GB file with `tx` and compared the MD5 sums of the sent and received files.

## Design Decisions

### Rust Crate Set

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | socket-mux is implemented in Rust on the standard library's blocking threads, synchronization and networking, with no async runtime. The crate set is `socket2` for socket options, `lexopt`, `anyhow`, `log`, `env_logger`, and `crossbeam-queue` for lock-free bounded queues; on Unix, `signal-hook` for SIGINT and SIGTERM and `libc` for thread priority and the adapter list; on Windows, `windows-sys` for Winsock, the console control handler, thread priority and the adapter list. Tokio is not a dependency.                                                                                                                                            |
| Rationale         | A fixed set of N long-lived lane sockets maps directly onto one blocking thread each, which the standard library and `socket2` provide on Linux, macOS and Windows ([Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io)). Blocking calls sleep in the kernel without CPU, so an async scheduler adds a hop and a shared core without adding capacity. Small queue and signal crates avoid hand-written lock-free and Unix signal code; `signal-hook` delivers each signal to an ordinary blocking thread, so no work runs in signal context. The Windows console handler already runs on its own thread, so `windows-sys` covers it without another crate. |
| Alternatives      | Tokio's current-thread runtime for TX and RX I/O; Tokio for the control plane only, beside per-lane threads; `pico-args` instead of `lexopt`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Rejection reason  | On the current-thread runtime TX sent about 5.2 Gbit/s at every lane count and TX and RX each saturated one core ([Measured Link Behavior](#measured-link-behavior)). A control-plane-only runtime keeps a second concurrency model and dependency for work that blocking threads and the signal crate already cover. `lexopt` is the selected parser.                                                                                                                                                                                                                                                                                                              |
| Affected surfaces | TX and RX I/O; signal handling; CLI; platform dependencies                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

### Session Identity And Restart

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | Add a random 16-bit session ID per TX run to every datagram header. TX logs the ID at startup. RX locks onto the first valid datagram's session and checks session before sequence placement, including for a datagram the buffer rule drops. A different session makes RX abort, and a new stream uses a fresh RX; the [specification](spec.md#semantics) owns the abort's observable effects, the exit status and no-resume behavior.                            |
| Rationale         | An explicit run identity lets RX distinguish a restart from late slices of the current run without scanning payloads or adding an application checksum. Aborting keeps two runs from being conflated in one output or one run's loss counts, and the failure status tells the caller that the run did not end normally. A 16-bit ID adds two header bytes; its collision and stale-first-datagram limits are admitted in [known issues](known-issues.md#register). |
| Alternatives      | No stream identity; seed a per-datagram application checksum; end the stream as end of stream does, with status 0.                                                                                                                                                                                                                                                                                                                                                 |
| Rejection reason  | Without identity, a new run's low sequence numbers look late until ipd ends the old stream. No per-datagram application checksum exists to seed; introducing one costs a full pass over every payload plus the header bytes. The pattern's per-block Adler-32 is separate from the datagram header. Ending as end of stream does reports an interrupted run as a normal end.                                                                                       |
| Affected surfaces | S-05; TX header/startup logging; RX session gate and abort; specification diagnostics S-17 and S-18; 24-byte header and 1428-byte payload at a 1500-byte MTU                                                                                                                                                                                                                                                                                                       |

### Inter-Packet Delay

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | RX decides every loss and the end of the stream with one inter-packet delay, ipd, a window of W and the buffer rule, under the loss rules the [specification](spec.md#semantics) owns. RX records each datagram's arrival time, keeps one deadline, the last-delivery time plus ipd, and the arrival time of its last buffer-rule drop, and checks them against a monotonic clock.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Rationale         | socket-mux is a formal statistical tool, so a loss count must come from a small, fixed rule that reproduces from the arrivals. One ipd from the last delivery bounds the delay any loss adds, and the same rules apply inductively to every later gap. Consecutive sends are about 1 µs apart at line rate, so the datagrams after a missing next were due at about the same time, and one ipd covers the whole stretch. When nothing arrived during ipd, no datagram is in flight and the stream is over; expiry with datagrams held is ordinary loss. RX holds the datagrams that arrive within ipd, so W ≥ r × ipd at arrival rate r. At loss rate p a gap is open about p × r × ipd of the time, so ipd well below 1 ÷ (p × r), about 1.2 ms at p = 10^-3 and about 820,000 datagrams/s, keeps RX mostly delivering. ipd must exceed the largest inter-lane skew, or reordered datagrams count as lost and then late. The [specification's](spec.md#rx-options) 1 ms default needs W of only about 820 datagrams at about 820,000 datagrams/s; it assumes inter-lane skew well below 1 ms, which the recorded largest out-of-sequence delay checks. |
| Alternatives      | Release a gap only when the reorder buffer fills; a timer per lane, or a rule that declares a gap lost on a later arrival in the same lane; a separate stall option; a full ipd per missing datagram, applied inductively; a 10 s timeout T with separate rules for gaps and for the end of the stream; a start-of-stream anchor that waits for older sequence numbers from the first arrival; RX waits until stopped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Rejection reason  | Buffer-fill release keeps the buffer full when p × r × W is large, and each loss then costs W ÷ r of delay. A per-lane timer fires on a dead lane while the others carry data, and a per-lane loss rule is a second rule whose counts depend on lane assignment. A separate stall option is another parameter, and an extra parameter confuses the data scientist reading the counts. A full ipd per missing datagram makes a burst of k losses cost k × ipd. A 10 s timeout holds every gap and the tail for seconds, and separate gap and end rules answer one question twice. A start-of-stream anchor is a second rule for the first gap; sequence 0 starts every session, so the ordinary rules cover it. Waiting until stopped leaves a lost end of stream open.                                                                                                                                                                                                                                                                                                                                                                                  |
| Affected surfaces | RX options; RX reordering and loss declaration; RX output; S-04, S-09, S-27                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

Each receive thread publishes, in one atomic word, whether it holds a stamped arrival not yet queued: it sets the mark before it reads the clock and clears it after the push. Before resolving an expired deadline, the reorder thread confirms that no lane is marked. While a mark stays set it keeps taking published arrivals, so a receive thread blocked on a full arrivals queue completes its push and clears its mark, and it processes every arrival at or before the deadline before resolving it; a lane found unmarked stamps any later arrival after that check, so no arrival at or before the deadline is still unpublished. Bounded queues and a fixed pool keep memory bounded. TX batches spread the cost of one queue hand-off over up to 32 datagrams; with one lane, a send thread would add a hand-off without spreading the send cost over more cores. A cap on arrivals per turn keeps output moving to the writer during a burst, and vectored writes cut the TCP write calls per datagram.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

### Wait Policy

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | Socket waits are blocking send and receive calls; no thread polls a socket or sets it nonblocking to spin on it. A thread waiting on a queue or the free list spins with 1, 2, 4 and so on up to 64 spin hints, 127 in all, then yields 3 times, then parks for 16 µs, doubling to 1024 µs, each park cut short by a notify, then parks until the producing thread notifies it. Work resets this ladder to its first spin. Producers notify after every push, which costs one fence and one load when no thread is waiting. The reorder thread has one deadline, the last-delivery time plus ipd, and parks no later than it, or, once it has passed while only buffer-rule drops keep the stream open, no later than the last drop's arrival time plus ipd. Its wake-up can come late by the platform's scheduling latency; it then takes published arrivals and the expired deadline in arrival-time order, as the [specification](spec.md#semantics) requires, after confirming that no arrival is unpublished ([Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io)), so a late wake-up delays a declaration but never changes which arrivals fall within ipd. No thread waits on a send schedule. The reporter waits on the loss ring. |
| Rationale         | A short spin catches the next datagram within nanoseconds at line rate without a kernel wake per datagram, about 0.8 million datagrams per second at 9.4 Gbit/s of 1452-byte datagrams (arithmetic). Backoff to a blocking park lets an idle TX or RX, and an RX holding datagrams behind a gap, use approximately 0 % CPU; an idle thread reaches the untimed park within about 2 ms. Every RX datagram buffer comes from it and passes by pointer, never copied, from a receive thread to the reorder thread to the writer staging, which keeps it until its TCP write completes. Free buffers sit on a lock-free free list, O(1) to take from and to return to, that the lane receive threads take from and the TCP writer returns to. The reorder thread keeps held datagrams in a ring of rings of buffer pointers. The outer ring has W slots indexed by sequence number mod W, each holding the pointer, exact sequence number and arrival time of one held datagram, the settled mark of a sequence number the buffer rule dropped, or nothing, so placement and the duplicate check are O(1); the window rule keeps every held or settled sequence number below next + W, so each has its own slot. Each contiguous held run is recorded at its two boundary slots, the first naming the last and the last the first, so an arrival merges with its neighbours in O(1); an occupancy bitmap, scanned 64 slots per word, finds the next held run once per gap, and each gap is one loss stretch. A bitmap of W bits records which of the W sequence numbers before next were declared lost, telling a late datagram from a duplicate; an older one counts as late. Delivery hands the run at next to the writer as one pointer range: the writer staging is a ring of W pointers, which never fills because the arena has W buffers, written with vectored TCP writes, and each buffer returns to the free list when its write completes. For the out-of-sequence delay the reorder thread keeps, in arrival order, each held datagram that arrived as the highest held sequence number, so their sequence numbers and arrival times both increase; a datagram arriving below the highest held one finds the first of them above it by binary search, stores its delay from that arrival in its slot and, when it is delivered, reports that delay through the loss ring; entries leave the list from the front as next passes them. The reorder thread applies the buffer rule to each drop a receive thread reports: unless its sequence number is late or a duplicate, it applies the window rule, counts the sequence number lost, cause `window`, and marks it settled. While the pressure flag is raised and a held run follows a missing next, it releases that head gap under the buffer rule, without waiting for ipd, and repeats while both hold; the run it hands to the writer frees its buffers as they are written. It applies the window rule at placement and waits for its input queue until its one deadline ([Wait Policy](#wait-policy)). The slot array, bitmaps, pointer rings, queues and lane header areas are fixed overhead outside the arena. At the 1 ms default a gap holds about 820 of the default W of 46218 buffers, so the arena fills mainly when the TCP reader falls behind (derivation). Dropping the newest arrival is O(1) and touches no ring another thread owns; releasing the stranded head gap frees buffers by delivering data already received, at the cost of declaring that gap before ipd. | Alternatives      | A separate writer staging of W more buffers with its own `output` cause; transit buffers beyond the arena; a spare datagram buffer per lane; a receive thread waiting for a free | Rejection reason  | A separate staging, transit allowance or spare buffer takes RX's memory beyond the configured limit; waiting leaves the drop to the kernel, which RX does not count; LRU eviction needs a lane thread to change the ring the reorder thread owns, a higher implementation risk, and discards data already received; and an `output` cause only tells a slow reader from a short window, which is not worth a second rule because any loss can result from a slow reader. A memory reserve ties loss to how fast the TCP reader drains the output, so the same link loss gives different counts with different readers, and a count is not reproducible. A heap costs O(log H) per insert, where H is the number of datagrams held. ### Loss And Summary Reporter

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | The reorder thread keeps exact counters of lost slices per loss cause, total lost bytes and late and duplicate drops, published without locks; the TCP writer keeps the delivered-byte and delivered-datagram counters. Loss stretches and out-of-sequence delays leave the data path only as compact fixed-size entries in a bounded single-producer, single-consumer ring of 4096 entries, so a push is wait-free: for each loss gap it settles the reorder thread pushes one entry carrying cause, first sequence number, slice count and byte length, and for each datagram it delivers with an out-of-sequence delay one entry carrying that delay and the datagram's arrival time; an in-order delivery pushes nothing. No data-path thread waits on the ring or formats a line: when the ring is full the entry is discarded and the `events_dropped` counter is incremented. One reporter thread, at nice +10 on Linux and below-normal priority on Windows, drains the ring as fast as it can, waiting under the [Wait Policy](#wait-policy) only while it is empty; it merges consecutive gaps of one cause into one stretch, prints each group of stretches it drains as one `warn` loss warning and keeps the largest delay of the run; no line reports a delay per datagram, and no interval report prints at `info`. When the run ends, or a signal or the watchdog asks, it drains the ring again and prints the final summary. TX keeps sent-byte and datagram counters, and its reporter prints the TX final summary the same way. The [specification](spec.md#diagnostics) owns the reported facts. |
| Rationale         | Loss reporting must never interfere with the critical path or maximum throughput. Formatting and writing a log line per loss stretch on the ordering path flooded the log under heavy loss and slowed RX into more loss ([Measured Link Behavior](#measured-link-behavior)). Exact counters keep totals correct even when the ring overflows; the ring keeps per-stretch detail, the stretch count and longest stretch, off the hot path. Loss warnings show loss as it happens at `warn`, and `info` carries only the final summary; a line per out-of-sequence datagram is too fine grained even for a trace, so the reporter aggregates delays. Merging consecutive gaps of one cause reports one stretch where the reorder thread settled a run in pieces, such as consecutive buffer-rule drops of one datagram each. A lower thread priority keeps the reporter from competing with the data-path threads for a core.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Alternatives      | One log line per loss stretch; per-stretch lines rate-limited to a fixed number per second with the rest summed; interval reports at `info`; a blocking channel from the reorder thread to the reporter.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Rejection reason  | Per-stretch lines are unbounded hot-path logging ([constraints](constraints.md)). Rate limiting still formats and writes lines on the reorder thread. Interval reports put periodic lines at `info` before the stream ends. A blocking channel lets a slow reporter stall ordering.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Affected surfaces | S-09, S-22, S-26; reorder thread; reporter                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

### Signal Handling And Final Summary

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | `tx`, `tx-pat` and RX install a handler for SIGINT and SIGTERM through `signal-hook` on Unix, and a console control handler for the Ctrl-C and console-close events through `windows-sys` on Windows ([Rust Crate Set](#rust-crate-set)). On Unix, `signal-hook` delivers each signal to a dedicated blocking thread; on Windows the console control handler runs on its own thread. The handler records the first signal, logs it and sets the run's stop. The stop wakes every parked waiter and runs hooks that unblock threads in blocking calls: it shuts the TCP connections, sends an empty datagram to each RX lane socket so its receive returns, and connects to a `tx` listener still waiting for its client. TX then sends no end-of-stream datagram; the RX reorder and writer stop, so held and unwritten datagrams are not delivered. The reporter drains the loss ring and prints the final summary, and the process exits with 128 plus the signal number. A second signal exits at once with the first signal's status. A watchdog thread waits 2 s after the first signal and, if the process has not ended, prints the final summary and exits with that status. On Windows the console control handler maps Ctrl-C and Ctrl-Break to SIGINT and status 130, and closing the console, logoff and shutdown to SIGTERM and status 143; this Windows mapping has not yet been compiled for or run on Windows. |
| Rationale         | Measurement runs and long transfers end by a signal; the final summary must survive that end, and 130 and 143 follow the shell convention of 128 plus the signal number. Recording the signal and setting the stop keeps the handler trivial; the data-path threads end through the same stop flag and wake-ups they already check. Unblocking hooks let a thread blocked in a socket call leave it without a timeout, and the watchdog still bounds the end when a read cannot be unblocked, such as standard input from a terminal.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Alternatives      | The operating-system default disposition, with no handler.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Rejection reason  | The default disposition ends the process before any summary, so the run's loss and rate are lost.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Affected surfaces | S-23; M-01; reporter                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

### No TX Pacing

| Field             | Value                                                                                                                                                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Decision          | TX sends each datagram as soon as its lane accepts it. Neither `tx` nor `tx-pat` has a pacing or inter-packet delay setting; inter-packet delay is RX's ([Inter-Packet Delay](#inter-packet-delay)).                                       |
| Rationale         | In link sweep `20261030T011330Z`, goodput fell with every pacing interval, to about 1428 × 8 ÷ interval Gbit/s, and paced runs still lost datagrams to adapter misses and miss bursts ([Measured Link Behavior](#measured-link-behavior)). |
| Alternatives      | `tx-pat --ipd-ns NS`, a due-time schedule across all lanes, unpaced by default.                                                                                                                                                            |
| Rejection reason  | It lowered goodput at every interval measured and did not reduce loss.                                                                                                                                                                     |
| Affected surfaces | TX path; M-05, M-06, M-13; `tx-pat`                                                                                                                                                                                                        |

### UDP Socket Buffer Sizing

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | `--udp-buffer` requests each UDP send buffer on TX and each UDP receive buffer on RX; without it both sides keep the operating-system default. TX and RX read the effective size back and report a capped request ([specification](spec.md#diagnostics)). Operators size the RX receive buffer and leave the TX send buffer at the default.                                                                                                                                                                                                                                                                                           |
| Rationale         | An RX receive buffer that is too small overflows into UDP receive-buffer errors: with the build before the thread-per-lane rewrite 4 MiB overflowed at about 9.4 Gbit/s and 16 MiB or more did not, and the thread-per-lane build counted none at 4 MiB or more in the link sweep; a large TX send buffer lets the sending host queue more than the link carries and drop datagrams in its queueing discipline ([Measured Link Behavior](#measured-link-behavior)). Linux caps each request at `net.core.rmem_max` or `net.core.wmem_max`, which only an administrator raises, so the readback makes a cap visible instead of silent. |
| Alternatives      | One large default buffer on both sides; a larger default RX receive buffer, such as 16 MiB or 64 MiB, with the TX default unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Rejection reason  | A large TX buffer causes sender-side drops ([constraints](constraints.md)). Linux caps an RX request at `net.core.rmem_max`, 4194304 bytes by default, until an administrator raises it, so a larger RX default cannot raise the buffer by itself and would log the capped-request warning on every RX start on a host whose cap was not raised.                                                                                                                                                                                                                                                                                      |
| Affected surfaces | `--udp-buffer`; S-19; M-04                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

### Datagram Size From Adapter MTU

| Field             | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decision          | Without `--datagram-size`, each side sets its datagram size to its adapter MTU less 48 bytes, limited to 65507. TX resolves `--remote`, connects a probe UDP socket, which sends nothing, to the first resolved address at the base port, and takes the adapter that owns the local address the operating system selected. RX takes the adapter the [specification](spec.md#terminology) selects for its `--bind` address, and the first listed adapter wins a tie. The derived size is clamped to 25 to 65507. When the MTU cannot be read, the default is 1452. The size and its source are logged once at `debug`; when the datagram size, given or derived, exceeds the adapter MTU less 48, the side also logs one warning and proceeds. W is computed from the effective size, so the route probe and the adapter query precede the `--rx-memory` check in the order the [specification](spec.md#invalid-combinations) states.                                                                                                |
| Rationale         | A sensible datagram size depends on the link: a datagram above the MTU less 48 bytes (the 40-byte IPv6 and 8-byte UDP headers) is fragmented, and losing one fragment loses the whole datagram ([Measured Link Behavior](#measured-link-behavior)), while a datagram well below the MTU sends more datagrams per second for the same rate. Deriving the default from the selected adapter fits one datagram to one frame of that adapter, including jumbo frames, without the operator computing it; a smaller MTU elsewhere on the path is not detected. For a wildcard RX bind the adapter that carries the link is the intended one; excluding loopback keeps its 65536-byte MTU from becoming the default, which would make each datagram about 45 times larger and W about 45 times smaller at the same RX memory limit. 1452 is a 1500-byte MTU less 48, the common Ethernet case. A single warning tells the operator of a size that fragments without blocking deliberate fragmentation runs or adding a line per datagram. |
| Alternatives      | A fixed default of 1452; refusing a datagram size above the adapter MTU less 48; no check of a given size; for a wildcard RX bind, the largest MTU among all adapters that are up, loopback included.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Rejection reason  | A fixed 1452 fragments nothing on a 1500-byte link but wastes jumbo frames and fragments on an adapter with a smaller MTU. Refusing blocks deliberate fragmentation runs such as the datagram-size sweep of `scripts/link-sweep`. No check leaves fragmentation loss silent. Counting loopback lets its 65536-byte MTU set the size for a wildcard bind on every host.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Affected surfaces | `--datagram-size`; S-14; S-24; S-25; M-01; M-02; M-12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

## Component Responsibilities

| Role                         | Responsibility                                                                                                                                |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| TX producer (`tx`, `tx-pat`) | Read or generate one stream, apply `--bytes`, sequence slices and frame each datagram for its lane; with N = 1, also send it, without pacing. |
| TX lane send thread          | With N ≥ 2, send its lane's datagrams as soon as it receives them, with blocking calls on its connected socket and return their batches.      |
| RX lane receive thread       | Receive its lane's datagrams into arena buffers with blocking calls and pass them, with arrival times, to the reorder thread.                 |
| RX reorder thread            | Apply the session rule, order slices, apply the loss rules, count loss and deliver in-order runs.                                             |
| RX TCP writer thread         | Write the staged runs as the reconstituted stream and return written buffers to the free list.                                                |
| Reporter                     | Print loss warnings and TX and RX final summaries, including after a signal.                                                                  |
| Checker (`check-pat`)        | Independently scan RX output and report pattern validity and resynchronization.                                                               |

## API Shape

The package exposes a command-line binary, not a Rust library API ([`Cargo.toml`](../Cargo.toml), [`src/main.rs`](../src/main.rs)). The [specification](spec.md#public-surface) owns the CLI and the UDP datagram shape. `SM-01` is the only cross-role data seam; this design describes its architectural use and does not duplicate its field schema.

## Workflow And Data Flow

TX sends lane k to `--remote` at base port + k, while RX listens on those same ports. Sequence s is assigned to lane s mod N. A full lane queue makes the TX producer wait, so TX runs at the rate its lanes accept; RX sends no backpressure to TX. A slow TCP consumer keeps arena buffers in the writer staging; the receive threads keep receiving, and once no arena buffer is free the buffer rule drops new datagrams as `window` loss and the reorder thread releases the gaps before held runs. Loss and delay entries and counters flow to the reporter without blocking.

```text
TX:  input or pattern -> producer -> lane queue k -> send thread k -> UDP base port + k   (k = 0 .. N-1)
RX:  UDP base port + k -> receive thread k -> reorder thread -> writer staging -> TCP writer -> original stream
     arena free list <- TCP writer;  receive thread k <- arena free list
     reorder thread -> loss ring and counters -> reporter -> loss warnings and final summary
     RX output -> check-pat
```

## Failure Modes

- **Datagram loss.** RX determines packet loss and the length of that loss from the headers; nothing is retransmitted ([No Retransmission](#no-retransmission)). The [specification](spec.md#semantics) owns what RX reports where it detects loss. RX declares loss only under the [specification's](spec.md#semantics) loss rules ([Inter-Packet Delay](#inter-packet-delay), [RX Ring Of Rings And Writer Staging](#rx-ring-of-rings-and-writer-staging)).
- **Deep reorder or fast burst.** A datagram W or more ahead of next declares the gap at next lost under the window rule before ipd; W of at least the arrival rate times ipd avoids it. A datagram reordered by more than ipd is declared lost under the ipd rule and dropped as late when it arrives ([Inter-Packet Delay](#inter-packet-delay), [RX Ring Of Rings And Writer Staging](#rx-ring-of-rings-and-writer-staging)).
- **Stalled TCP output.** TX waits only for completion of its own UDP sends; RX applies no backpressure to TX. The RX receive threads keep receiving while datagrams wait for their TCP writes until no arena buffer is free; then the buffer rule drops arrivals as `window` loss and the gaps before held datagrams are released before ipd ([Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io), [RX Ring Of Rings And Writer Staging](#rx-ring-of-rings-and-writer-staging)).
- **Pause in the TX input.** A pause longer than ipd in the stream TX reads, with nothing held or dropped at RX since its last delivery, ends RX's stream without its end-of-stream datagram; the programs feeding TX and reading RX buffer their own delays ([Inter-Packet Delay](#inter-packet-delay)).
- **Heavy loss.** Report entries beyond the loss ring's capacity are discarded and counted; loss totals stay exact and the data path is not slowed ([Loss And Summary Reporter](#loss-and-summary-reporter)).
- **Small socket receive buffer.** An RX receive buffer that is too small overflows, which the host counts as UDP receive-buffer errors and RX reports as loss; on Linux an administrator must raise `net.core.rmem_max` before a larger `--udp-buffer` takes effect ([UDP Socket Buffer Sizing](#udp-socket-buffer-sizing)).
- **Large TX socket buffer.** The sending host queues more than the link carries and its queueing discipline drops datagrams ([UDP Socket Buffer Sizing](#udp-socket-buffer-sizing)).
- **Adapter receive-ring overflow.** At rates from about 3.8 Gbit/s to line rate the RX host's adapter misses rare datagrams before any socket, even with TX pacing; RX reports them as ordinary loss ([Measured Link Behavior](#measured-link-behavior), [known issues](known-issues.md#register), [roadmap R-34](roadmap.md#r-34-linux-rx-adapter-receive-tuning)).
- **Adapter miss burst at stream start.** In 10 of 162 measured runs on 10GbE the RX host's adapter missed 16,908 to 1,630,967 datagrams at once, within the first 2 s of the stream wherever the measured build's interval lines locate the burst, so the run misses the [specification's](spec.md#boundaries) 99.9 % error-rate target; socket buffers, TX pacing and CPU pinning do not prevent it, and its mechanism is not known ([Measured Link Behavior](#measured-link-behavior), [known issue KI-13](known-issues.md#ki-13-adapter-miss-bursts-at-stream-start)).
- **Datagram above the path MTU.** A datagram size above the path MTU less 48 bytes is IP-fragmented; losing any fragment loses the datagram, so loss rises sharply. A size above the side's own adapter MTU less 48 draws one warning at start; a smaller MTU elsewhere on the path draws none ([Datagram Size From Adapter MTU](#datagram-size-from-adapter-mtu), [known issues](known-issues.md#register)).
- **TX restart or stale session.** A different session makes RX abort with end reason `error`, not a sequence reset, a flush or a resume ([Session Identity And Restart](#session-identity-and-restart)); same-ID collisions and stale-first arrivals remain [accepted limits](known-issues.md#register).
- **Dead lane.** RX reports every gap a later datagram exposes. If the dead lane carried the end-of-stream datagram, the ipd rule ends the stream ipd after the last delivery, without it ([Inter-Packet Delay](#inter-packet-delay)).
- **Signal.** SIGINT or SIGTERM ends TX or RX with its final summary and status 130 or 143, without an end-of-stream datagram from TX or delivery of RX's held datagrams; a run that does not end within 2 s is ended by the watchdog ([Signal Handling And Final Summary](#signal-handling-and-final-summary)).

## Acceptance Criteria

- **AC-01:** TX assigns sequence s to lane s mod N and sends lane k to the same base-port-plus-k endpoint on which RX listens, as required by the [specification](spec.md#semantics).
- **AC-02:** RX delivers in order and applies the specified ipd, window and buffer rules, as the specification's worked examples show, without retransmission or feedback to TX ([specification](spec.md#semantics)).
- **AC-03:** `tx-pat` output can be sent through RX and independently checked by `check-pat`, including recovery after loss ([Back-To-Back Verification Loop](#back-to-back-verification-loop), [specification validation](spec.md#validation)).
- **AC-04:** Settings remain command-line-only and both endpoints rely on operator agreement rather than negotiation ([Command-Line Options](#command-line-options), [specification](spec.md#semantics)).
- **AC-05:** TX and RX run without an async runtime: one send thread per TX lane when N ≥ 2, and the producer sending itself when N = 1, one receive thread per RX lane, one reorder thread and one TCP writer thread, and RX keeps receiving while its TCP output is stalled ([Thread-Per-Lane Blocking I/O](#thread-per-lane-blocking-io)).
- **AC-06:** An idle TX or RX, and an RX holding datagrams behind a gap, uses approximately 0 % CPU, and no socket is polled ([Wait Policy](#wait-policy), [specification invariants](spec.md#invariants)).
- **AC-07:** Under induced heavy loss, RX prints no line per lost datagram or per loss stretch at `info`, its lost-slice totals are exact, and loss-ring overflow is counted rather than waited on ([Loss And Summary Reporter](#loss-and-summary-reporter)).
- **AC-08:** SIGINT and SIGTERM end `tx`, `tx-pat` and RX with their final summary and status 130 or 143 ([Signal Handling And Final Summary](#signal-handling-and-final-summary), [specification exit status](spec.md#exit-status)).
- **AC-09:** Without `--datagram-size`, TX and RX use their adapter MTU less 48 bytes, or 1452 when the MTU cannot be read, and a datagram size above the adapter MTU less 48 produces exactly one warning per side while the run proceeds ([Datagram Size From Adapter MTU](#datagram-size-from-adapter-mtu), [specification diagnostics](spec.md#diagnostics)).
- **AC-10:** `rx --ipd` accepts and refuses values exactly as the specified `DURATION` grammar states, other subcommands refuse it, and neither `tx` nor `tx-pat` accepts a pacing setting ([Inter-Packet Delay Spelling](#inter-packet-delay-spelling), [No TX Pacing](#no-tx-pacing)).
- **AC-11:** `--bytes`, `--rx-memory` and `--udp-buffer` accept and refuse byte counts exactly as the [specification](spec.md#byte-counts) states ([Command-Line Options](#command-line-options)).
- **AC-12:** A different session makes RX abort as the [specification](spec.md#semantics) states ([Session Identity And Restart](#session-identity-and-restart)).
