# socket-mux Plan: Thread-Per-Lane Baseline To Qualified Platforms

## Scope

Bounded Change: take the thread-per-lane baseline that the [specification](../docs/spec.md) and [design](../docs/design.md) now describe from code landing to a requalified Linux x86_64 release target, then bring up the Windows peer and its tuning. Intended result: Linux x86_64 qualified again on this baseline, Windows x86_64 measured and qualified as the TX side to Linux RX, and the specification and design reconciled with the landed code. This is a direct Change from the 2026-10-29 owner rulings; it cites no roadmap seed.

Starting baseline: the specification, design, [constraints](../docs/constraints.md), [roadmap](../docs/roadmap.md) and [known issues](../docs/known-issues.md) as committed on 2026-10-29. At that baseline the code that realizes them was being rewritten in a separate concurrent Change, and the code before that rewrite ran TX and RX on an async runtime and logged each loss gap.

Remaining work, each stated as the gap between the current baseline and its target. A gap becomes a row in a `dc-doc-gap` inventory at `.planning/gaps.md` only once its shortfall is established against an admitted target with checkable evidence; open questions stay with their owner.

Assumptions: the two Linux 10GbE hosts keep `net.core.rmem_max` and `net.core.wmem_max` raised to 64 MiB, which lasts until reboot (`scripts/admin/sm-udp-buffers.sh`); the RX side of every qualification run sets `--udp-buffer` to 64 MiB, the link sweep varies it over 4, 16 and 64 MiB, and TX keeps the operating-system default.

Out of scope: Linux aarch64 qualification and the macOS re-test (deferred in R-42), thread pinning (R-43), batched I/O (R-32, R-33), kernel bypass (R-38) and the optimization loop (R-41).

## Authority

- Planning authority: the project owner's rulings of 2026-10-29 (no polling, loss reporting off the critical path, `--bytes` and `--ipd-ns` as product options, no async runtime, the planning reset), captured in the specification, design, constraints, roadmap and authority index; and of 2026-10-30 (default lane count 1 with README command lines for more lanes, one warning above the adapter MTU less 48, the datagram-size default derived from the adapter MTU, the RX socket-buffer default left at the operating-system default, and the tool's purpose), captured in the goals, specification, design, known issues and README.
- Behavior is owned by the specification, mechanism by the design, forbidden patterns by the constraints, prospects by the roadmap, residuals by the known issues ([authority index](../docs/index.md#authority-basis)). This plan restates none of them.
- No owner decision is open for `P1` to `P6`; a decision is written into its owner before any code follows it.
- Code owner: the concurrent code Change for `P1`; documentation owner for `P2`; the project owner for qualification acceptance in `P3` and `P4`, and for host administration in `P5` and `P6`.
- Identifier mapping for `P2`, applied to the source and test comments that cited retired document identifiers: `SM-Dnn` is roadmap `R-nn` where that prospect remains, and in every case the design decision of the same subject (`SM-D11` is design Round-Robin Slice Assignment and RX Listen Ports, `SM-D19` is design Inter-Packet Delay Timeout, `SM-D20` the former Event-Driven I/O, now Thread-Per-Lane Blocking I/O and Wait Policy, `SM-D21` Inter-Packet Delay Timeout Spelling); `SM-Pnn` is specification `S-nn`; `SM-KI-nn` is `KI-nn`; `SM-R1` to `SM-R6`, `SM-R8` and `SM-R9` are `R-31` to `R-36`, `R-38` and `R-39`, with `SM-R1`'s pinning now `R-43`; `SM-R7` (a larger default RX buffer) is design [UDP Socket Buffer Sizing](../docs/design.md#udp-socket-buffer-sizing); `SM-W1` and `SM-W2` are `R-41` and `R-42`; `SM-AUTH-00n` is `A-0n`.
- Constraints applied: [constraints](../docs/constraints.md), the only constraints document on the authority basis; no step above plans a pattern that triggers one of its detection signals.

## Acceptance

- `P1`: the code Change's tests pass and cover design AC-05 to AC-09; accepted by the code Change's owner.
- `P2`: the design and specification lint clean and every realization note and identifier mapping matches the landed code; accepted by the documentation owner.
- `P3` and `P4`: the qualification runs in the specification's Boundaries pass on real machines; the project owner accepts the qualification and the specification's Boundaries are updated to record it.
- `P5` and `P6`: measured comparisons are recorded in the design's Measured Link Behavior; resulting decisions go to their owners and residuals to the known issues.

## Successor

- Applicability ends when `P1` to `P6` are each accepted or explicitly abandoned by the project owner.
- Surviving meaning goes to its current owners: qualification status to the specification's Boundaries, measurements to the design's Measured Link Behavior, residual loss to the known issues, and prospects to the roadmap, where completed prospects retire with successor references.
- At succession this plan and any `.planning/gaps.md` leave current reading routes.
