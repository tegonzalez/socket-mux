# socket-mux Plan: Thread-Per-Lane Baseline To Qualified Platforms

## Scope

Bounded Change: take the thread-per-lane baseline that the [specification](../docs/spec.md) and [design](../docs/design.md) now describe from code landing to a requalified Linux x86_64 release target, then bring up the Windows peer and its tuning. Intended result: Linux x86_64 qualified again on this baseline, Windows x86_64 measured and qualified as the TX side to Linux RX, and the specification and design reconciled with the landed code. This is a direct Change from the 2026-10-29 owner rulings; it cites no roadmap seed. The owner-agreed RX loss algorithm of 2026-10-30 extends it: the specification and design state that algorithm, the code does not yet conform to it, and Linux x86_64 is requalified on code that does. The owner's answers of 2026-10-30 to the local decisions register's OD-05 to OD-14 settle that algorithm's open choices and add byte-count suffixes and the session abort to the same realization.

Starting baseline: the specification, design, [constraints](../docs/constraints.md), [roadmap](../docs/roadmap.md) and [known issues](../docs/known-issues.md) as committed on 2026-10-29. At that baseline the code that realizes them was being rewritten in a separate concurrent Change, and the code before that rewrite ran TX and RX on an async runtime and logged each loss gap.

Remaining work, each stated as the gap between the current baseline and its target. A gap becomes a row in a `dc-doc-gap` inventory at `.planning/gaps.md` only once its shortfall is established against an admitted target with checkable evidence; open questions stay with their owner.

`scripts/admin` reads host limits and adapter MTUs and passes no socket-mux option, so the replacement cannot reach it.

Cutover condition: one commit on `main` lands `P7.1` to `P7.5` with the `scripts/link-sweep` rewrite, after its loopback check passes, and the README and design realization rewrites. Before it, the code keeps `--timeout`, the wheel and pacing, and the specification and design are the authority for the target; after it, no build accepts `--timeout` or `--ipd-ns`, the retired tests are gone, and no repository script passes either option.

Assumptions: the two Linux 10GbE hosts keep `net.core.rmem_max` and `net.core.wmem_max` raised to 64 MiB, which lasts until reboot (`scripts/admin/sm-udp-buffers.sh`); the RX side of every qualification run sets `--udp-buffer` to 64 MiB, the link sweep varies it over 4, 16 and 64 MiB, and TX keeps the operating-system default.

Out of scope: Linux aarch64 qualification and the macOS re-test (deferred in R-42), kernel bypass (R-38), the optimization loop (R-41), and pinning lane threads to cores and batched UDP I/O, which are not roadmap prospects but open owner questions in this Change's local decisions register.

## Authority

- Planning authority: the project owner's rulings of 2026-10-29 (no polling, loss reporting off the critical path, `--bytes` and `--ipd-ns` as product options, no async runtime, the planning reset; the `--ipd-ns` ruling is superseded below), captured in the specification, design, constraints, roadmap and authority index; and of 2026-10-30 (default lane count 1 with README command lines for more lanes, one warning above the adapter MTU less 48, the datagram-size default derived from the adapter MTU, the RX socket-buffer default left at the operating-system default, and the tool's purpose), captured in the goals, specification, design, known issues and README; and the further 2026-10-30 rulings that success is judged by total error rate, with three to five nines delivered on a 10 Gbit/s link through a single switch, and that Linux x86_64 is qualified on this baseline with caveats `KI-10` and `KI-13`, captured in the goals, specification, design and README; and the owner-agreed RX loss algorithm of 2026-10-30 (one inter-packet delay, `rx --ipd`, with units like a duration and a provisional default of 1 ms, made final by OD-05; no `--timeout` and no other loss setting; TX sends with no delays; outer senders and receivers buffer their own delays), which supersedes the 2026-10-29 ruling that `--ipd-ns` is a product option, captured in the specification, design, constraints, known issues, roadmap and README; and the owner's answers of 2026-10-30 to OD-05 to OD-14 in the local decisions register (a final 1 ms `--ipd` default, older-than-W datagrams counted late, no `output` cause, a wait-free report queue, `--ipd 0` refused, an `end` reason in the summary, one arena of `--rx-memory`, a dropped datagram as an arrival, a session abort, byte-count suffixes), captured in the specification, design and README.
- Behavior is owned by the specification, mechanism by the design, forbidden patterns by the constraints, prospects by the roadmap, residuals by the known issues ([authority index](../docs/index.md#authority-basis)). This plan restates none of them.
- Open owner questions in the local decisions register gate only their dependent work: OD-15 (how a lane receives a datagram when no buffer is free) and OD-16 (stream end while RX only drops) gate those parts of `P7.2`; OD-17 (the end reason after a runtime failure), OD-18 (separate grouped loss warnings), OD-19 (how many delay entries RX pushes and how each is attributed to its interval) and OD-20 (the delay's spelling) those parts of `P7.4` and `P7.5`. The rest of `P7` is ready. A decision is written into its owner before any code follows it.
- Code owner: the concurrent code Change for `P1`, and a code owner the project owner assigns for `P7.1` to `P7.4` and a different, independent test author for `P7.5`; documentation owner for `P2`; the project owner for qualification acceptance in `P3`, `P4` and `P9` and for host administration in `P5` and `P6`.
- Identifier mapping for `P2`, applied to the source and test comments that cited retired document identifiers: `SM-Dnn` is roadmap `R-nn` where that prospect remains, and in every case the design decision of the same subject (`SM-D11` is design Round-Robin Slice Assignment and RX Listen Ports, `SM-D19` is design Inter-Packet Delay, `SM-D20` the former Event-Driven I/O, now Thread-Per-Lane Blocking I/O and Wait Policy, `SM-D21` Inter-Packet Delay Spelling); `SM-Pnn` is specification `S-nn`; `SM-KI-nn` is `KI-nn`; `SM-R1`, `SM-R4` to `SM-R6`, `SM-R8` and `SM-R9` are `R-31`, `R-34` to `R-36`, `R-38` and `R-39`, while `SM-R2`, `SM-R3` and `SM-R1`'s pinning are no longer prospects and their choices are open owner questions in the local decisions register; `SM-R7` (a larger default RX buffer) is design [UDP Socket Buffer Sizing](../docs/design.md#udp-socket-buffer-sizing); `SM-W1` and `SM-W2` are `R-41` and `R-42`; `SM-AUTH-00n` is `A-0n`.
- Constraints applied: [constraints](../docs/constraints.md), the only constraints document on the authority basis; no step above plans a pattern that triggers one of its detection signals.

## Acceptance

- `P1`: the code Change's tests pass and cover design AC-05 to AC-09; accepted by the code Change's owner.
- `P2`: the design and specification lint clean and every realization note and identifier mapping matches the landed code; accepted by the documentation owner.
- `P3` and `P4`: the qualification runs in the specification's Boundaries pass on real machines; the project owner accepts the qualification and the specification's Boundaries are updated to record it.
- `P5` and `P6`: measured comparisons are recorded in the design's Measured Link Behavior; resulting decisions go to their owners and residuals to the known issues.
- `P7`: the independently authored `P7.5` tests pass on the cutover commit, and the design's realization notes match the code; the `P7.5` test results are the acceptance evidence, separate from the code owner's own checks, and the project owner accepts them.
- `P9`: as `P3`, on a build of the `P7` code, with the measured largest out-of-sequence delay recorded in the design's Measured Link Behavior.

## Successor

- Applicability ends when `P1` to `P7` and `P9` are each accepted or explicitly abandoned by the project owner.
- Surviving meaning goes to its current owners: qualification status to the specification's Boundaries, measurements to the design's Measured Link Behavior, residual loss to the known issues, and prospects to the roadmap, where completed prospects retire with successor references.
- At succession this plan and any `.planning/gaps.md` leave current reading routes.
